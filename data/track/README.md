# 鉄路データ

鉄路は、列車を物理的に支持・案内する設備と、線路に沿って設置される集電設備で構成する。

## カタログ

| ファイル | 内容 |
|---|---|
| [`gauges.yaml`](gauges.yaml) | 軌間 |
| [`rail-profiles.yaml`](rail-profiles.yaml) | レール断面・単位重量 |
| [`support-systems.yaml`](support-systems.yaml) | 締結、枕木・支持構造、道床を一体化した軌道支持方式 |
| [`roadbeds.yaml`](roadbeds.yaml) | 軌道全体を下から支える人工的な路盤 |
| [`electrification-systems.yaml`](electrification-systems.yaml) | 架線・第三軌条と電気方式 |
| [`standards.yaml`](standards.yaml) | 構成要素を参照する建設・更新プリセット |

`rail-profiles.yaml`の`regionType`は規格系統を検索・分類するための広域分類であり、その地域以外で使用できないことを意味しない。初期値は`japan`、`europe`、`north-america`、`russia`、`australia`、複数地域へ広がった系統を表す`global`とする。`regionTags`は`britain`など、由来や実際の展開地域を詳しく表す補助分類である。

歴史的なレールでは、資料記載値とゲーム用モデル値を区別する。

- `massEvidence`: 単位質量の根拠。`documented`、`documented-class`、`estimated`、`modeled-class`
- `capabilityEvidence`: 軸重・速度性能の根拠。現段階の`modeled`はゲーム用推定
- `referenceMaxAxleLoadT`: ゲーム用の暫定参考軸重
- `referenceMaxSpeedKmh`: ゲーム用の暫定参考速度
- `typicalUses`: 代表的な用途。建設可否を固定する制限ではなく、検索、提案、AI判断の手掛かり

`introducedYear`は初出またはゲーム上の代表的な導入年、`typicalUntilYear`は典型的な使用が終わる目安であり、全線から消滅した年を意味しない。

## 責務の分離

- 軌間は車輪との物理互換性を決める
- レールは鉄路の一構成要素であり、単独で区間全体の軸重・速度を決めない
- 許容軸重と設計速度は、レール、軌道支持方式、路盤、構造物、線形、保守状態から決まる
- 電化方式は鉄路に含めるが、変電所とき電容量は`power-facilities/`で扱う
- 信号、閉塞、保安装置を鉄路プリセットへ埋め込まない

## 軌道支持方式と路盤

締結装置、枕木・その他の支持構造、道床は、相互依存が強いため`support-systems.yaml`の一つの軌道支持方式として定義する。締結装置を個別選択するデータにはしない。

路盤は軌道支持方式から分離する。同じ木枕木バラスト軌道でも、簡易土路盤、標準排水路盤、強化路盤などを組み合わせられる。

```text
レール
  ↓
軌道支持方式（締結＋枕木・支持構造＋道床）
  ↓
路盤
  ↓
マップ側の自然地盤
```

自然地盤は鉄路カタログへ含めない。マップ上の地質・湿地・岩盤などと路盤の組み合わせから、沈下、建設費、保守負担を計算する。

## `standards.yaml`

プリセットは構成要素への参照と、建設時の初期値をまとめる。上位互換のレベルではなく、用途と制約を持つ組み合わせとして定義する。

線路区間の実状態はプリセットIDだけに依存せず、交換された構成要素、老朽化、局所的な速度制限を個別に保持できる設計とする。

## 線路セグメント

地図上の線路は`TrackSegment`へ分割する。セグメント内では、線路規格、法的状態、敷設形態を変化させない。これらのいずれかが変わる地点をセグメント境界とする。

法的状態と敷設形態は別の属性として保持する。

- `legal.regulatorySystemId`: 適用する法制度。例: 鉄道事業法、軌道法
- `legal.operationType`: 鉄道または軌道としての扱い
- `installation.alignmentType`: 専用の線路敷、道路上、道路脇などの物理的な敷設形態
- `installation.roadRelationship`: 道路交通と空間を共用するか、道路内で分離されるか

```yaml
id: track-segment-001
trackStandardId: jp-tram-basic
legal:
  regulatorySystemId: jp-tramway-act # 軌道法に基づく区間
  operationType: tramway
installation:
  alignmentType: street-running # 道路上に敷設
  roadRelationship: shared-roadway # 一般道路交通と共用
```

専用部分から併用軌道へ移る場合は、切替状態を一つのセグメント内へ持たせず、その地点で二つのセグメントへ分ける。

## 水平線形

ワールド座標は`1 unit = 1 m`として扱う。プレイヤーは自由な曲線を敷設でき、工学上の最小曲線半径だけを理由に建設を禁止しない。

曲線半径はカタログ値ではなく、地図上の線路形状から求める。曲線上の各位置の局所曲線半径と区間内の最小曲線半径を計算し、複線以上では各線を個別に評価する。急曲線は、車両の通過可否、速度、摩耗、安全性、法令適合へ影響させる。

カントは通常のマップ描画には出さないが、建設された線路の内部状態として保持する。建設前に設計速度などから自動提案し、建設後は設備値として固定する。線路形状を変更した場合は半径を再計算するが、カントは自動変更せず、必要に応じて改修または速度制限を行う。

詳細は[`docs/designs/track-horizontal-alignment.md`](../../docs/designs/track-horizontal-alignment.md)を参照する。

速度制限、工事、災害、保守状態など、一時的または局所的に重なる条件はセグメント分割の必須条件にしない。これらは将来、対象範囲を指定できる別データとして扱う。

### 初期列挙値

| キー | 値 | 意味 |
|---|---|---|
| `operationType` | `railway` | 鉄道として扱う |
|  | `tramway` | 軌道として扱う |
| `alignmentType` | `exclusive` | 道路と共用しない専用の線路敷 |
|  | `street-running` | 道路上に敷設 |
|  | `roadside` | 道路に沿うが道路面を共用しない |
| `roadRelationship` | `none` | 道路との共用関係なし |
|  | `shared-roadway` | 一般道路交通と路面を共用 |
|  | `reserved-lane` | 道路内の分離された部分を使用 |

列挙値は物理状態を表す機械用の語彙とし、「専用軌道」「併用軌道」などのゲーム内表示は属性の組み合わせから決定する。

## 軌道状態と荷重

軌道状態は線路規格そのものではなく、使用と保守によって変化するセグメントの状態として保持する。状態が変化するたびにセグメントを分割せず、セグメントまたはセグメント内の対象範囲へ重ねて記録できるようにする。

劣化の作用を一つの「良好・普通・不良」だけで表さず、少なくとも次の二つに分ける。

| 状態 | 意味 | 計算への作用 |
|---|---|---|
| `geometryCondition` | 高低・通りなど、軌道形状の健全度 | 動的荷重の増幅率へ作用する |
| `structuralCondition` | レール、軌道支持方式、路盤の健全度 | 軌道が耐えられる荷重へ作用する |

値は`0.0`から`1.0`までの連続値とする。`1.0`は基準上良好な状態、`0.0`は使用不能な状態を表す。ゲーム内の「良好」「注意」「不良」などの表示は、この数値から求める。

```yaml
condition:
  geometryCondition: 0.92 # 軌道形状の健全度
  structuralCondition: 0.85 # 軌道構造の健全度
```

荷重計算は、概念的に次の順で行う。

```text
構成要素の耐荷重の最小値
  × 構造状態による耐荷重補正
  ＝ 現在の最大動的軸重

列車の静的軸重
  × 速度による動的増幅率
  × 軌道形状による増幅補正
  ＝ 軌道へ作用する動的軸重
```

作用する動的軸重が現在の最大動的軸重以下となる速度だけを許可する。最大線荷重は軸重とは別に判定する。補正式と係数は実測・設計資料を確認してから別の計算モデルとして定義し、現段階では固定しない。
