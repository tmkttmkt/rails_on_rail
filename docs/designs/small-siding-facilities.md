# 小側線施設の用途と入出庫試験

## 範囲

線路形状、施設のまとまり、用途、留置できる区間を分ける。既存Stationの非旅客kindを施設のまとまりとして利用し、任意のfacilityUse（unknown / stabling / headshunt / maintenance / depot）でゲーム上の用途を指定する。名称や最寄り駅から用途を確定しない。既存セーブの未指定はUIでは用途未確認と表示する。

共通MapCommandとして facility.registerTrack / setUse / prepareTrial / runTrial / removeTrial を実装する。UIとスクリプトは同じ命令を使用する。登録はside分類の線路に限定し、既存施設・旅客範囲と分岐支障を除いた20 m以上の範囲を作る。未指定の新施設はunknownとする。headshuntは入換の一時的用途であり留置配置の対象にしない。

## 小施設での試験

試験用保守車は仮想12 m・1067 mmの自走車1両で、実在車の性能を表さない。YAMLで車長・軌間・速度・距離条件を定義する。動力源や保守作業そのものはシミュレートしない。

prepareTrialは現存fleet/運転がないときだけ許可する。留置区間を再検査し、ホームから本線までの有向経路、反転後の復路、編成全長が停車位置に収まること、分岐支障、全経路の軌間を検査する。検査成功後にfleetへ個体・編成を作り、yardへ占有を置く。失敗時はexecuteCommandの複製処理により元状態を保持する。

往復は既存yardの4工程（出庫・反転・入庫・反転）で実行する。yard.facilityTrialに施設ID・編成ID・側線と本線の停止占有を保存する。既存の経路確保・占有競合処理と時間操作を使う。途中保存でも継続できる。最後の反転で初期位置・向きへ戻す。

用途変更・施設削除・線路編集は試験車の存在中に拒否する。撤収は元の側線位置に戻り停止しているときのみ許可する。本線上で試験車を消さない。試験の車両個体と編成だけを撤収する。

## 保存と互換性

未コミットのv14に任意のfacilityUseとyard.facilityTrialを追加した。既存のv13以前の移行経路と既存yard形式2を維持する。未知用途、旅客駅への施設用途付与、壊れた試験参照・停止位置・車両設計は読込時に拒否する。

## 今回の制限

試験中の営業運転との混在、信号・連動・加減速、架線・燃料、検査や洗浄、車庫全体の自動分類は対象外。既存yard全般や過去の車両へ軌間検査を遡及導入する変更ではない。今回の試験車と経路では1067 mm一致を必須にした。
