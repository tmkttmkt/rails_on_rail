# Design: 停車場と線路の運転上の区分

## 背景

現行モデルには次の2つが無い。

- **停車場の種類**。`Station` は旅客駅のみを想定しており、留置線・車両基地・
  操車場を表現できない。`fleet.formation.place` は駅の停車地点を要求するため、
  **旅客駅以外へ車両を置けない**。森林公園検修区にも、ベカソヴォ操車場の
  仕分線32本にも1両も置けない。
- **線路の区分**。本線と側線の区別が無い。OSM取り込みでは `service=yard` /
  `siding` の線路（東武東上線系統で17.8 km）が本線と同じ扱いで入る。

## 決定

両方を導入する。**この2つは直交しており、一方が他方の代わりにならない。**

```text
線路の区分   = その線路が何か         本線 / 側線
停車場の区分 = その場所が何か         駅 / 信号場 / 操車場 / 車両基地
```

実物でも両方が存在する。車両基地（場所）の中に留置線（線路）が並び、
側線は駅の中にもある。側線を分類しても車両を置けるようにはならず、
車両基地を作っても側線の扱いは変わらない。

### 停車場の種類

`Station` を日本の鉄道における**停車場**として扱い直す。停車場が上位区分であり、
駅・信号場・操車場はその種類である。構造を変えず `kind` を加えるだけで対応できる。

| kind | 表示 | 内容 |
|---|---|---|
| `station` | 駅 | 旅客・貨物の取り扱いを行う |
| `signal-box` | 信号場 | 行き違い・待避のみ。取り扱いを行わない |
| `yard` | 操車場 | 貨車の仕分けを行う |
| `depot` | 車両基地 | 車両の留置・検修を行う |

`StationStopPoint` は「線路上の範囲」であり旅客ホーム固有の概念を含まない。
車両配置は停車地点の範囲内であることだけを要求し、**同一線路上でも占有範囲が
重ならなければ複数の編成を置ける**（`fleet.formation.place` の既存実装）。
したがって仕分線・留置線は `kind` を変えた停車場の停車地点としてそのまま表現でき、
1本の線路へ複数の編成を留置できる。

### 線路の区分

| kind | 表示 | 内容 |
|---|---|---|
| `main` | 本線 | 列車の運転に使う |
| `side` | 側線 | 入換・留置・仕分に使う |

OSMの `service=yard` / `siding` / `spur` はいずれも側線へ対応付ける。

## 区分は性能ではなく運用の制約である

**本線・側線は設備規格が決めるのではなく、規格の上に乗る運転上の区分である。**
同じレールで敷いた側線は物理的には高速を出せるが、側線だから入換速度に制限される。

```text
設備規格（軌間・レール・支持方式・路盤）
   ↓ 規格上の上限
線形（曲線半径・カント）
   ↓ 曲線通過速度
運転上の区分（本線 / 側線）
   ↓ 側線は入換速度へ制限
= 実際の制限速度 = これらの最小値
```

したがって `Track.kind` に速度値を持たせない。制限速度を導出値にする改修は
**本設計の対象外**とし、別途設計する。現行の `designSpeedKmh`（敷設時の自由入力）は
当面そのまま残す。

## 公開インターフェース

```text
station.createRange   ... + kind?   省略時は station
station.setKind       stationId / kind
track.create          ... + kind?   省略時は main
track.setKind         trackId / kind
```

`station.merge` は統合先（先頭）の種類を引き継ぐ。

## 保存

ゲーム状態を version 13 とする。version 12 からは全停車場へ `kind: "station"`、
全線路へ `kind: "main"` を補うだけの加算的移行とする。

## 対象外

- 制限速度の導出（規格上限 ∩ 曲線 ∩ 区分）。別設計とする
- 種類ごとの運行上の扱いの差（旅客扱いの可否、通過の可否）
- 信号場・操車場における進路や閉塞
- 車両基地の検修能力、留置容量
- 側線のさらなる細分（留置線・引上線・仕分線など）
