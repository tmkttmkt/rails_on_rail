# 未確定旅客駅の保持と保存v14

駅ノードの存在と、運転に使用できる停車範囲の確定を分離する。線路や範囲を捏造せずに駅を保持するため、Stationへ任意の `unresolvedReason: string` を追加する。旅客駅に非空の理由がある場合だけstopPoints空配列を許可する。位置は元OSM駅ノードで保持する。

共通操作 `station.createUnresolved` は名前・位置・理由を受け取り、旅客駅を作る。理由は1〜1000文字。座標は有限値を必須とする。車両配置は既存の停車範囲検証により拒否する。未確定駅を他の施設種類へ変更する操作も拒否する。位置と名称・理由は地図と選択パネルへ表示する。

確定範囲がある駅を手動で統合すれば未確定理由を外す。未確定駅同士の統合は対象の位置と理由を保持し、0除算しない。無関係な線路の撤去で範囲0件の未確定駅を削除しない。

保存の許可条件が変わるためMapStateをv14とする。v13および以前の移行経路はv14へ到達し、旧データの駅と範囲を保持する。v14で理由なしの空駅は拒否する。新形式を旧コードが読めるという互換性は保証しない。

取込時は元operatorが局所線路に存在しない場合、元network、既知の駅と線路で一意に対応するref文字接頭辞、元operator欠損時には局所ホームに一致する事業者が1つだけという根拠を順に使う。複数一致は未確定。診断へ元値・解決値・根拠を記録する。確定駅の作成を先行し、失敗した候補の未確定駅化は最後に行って同名乗換ノードの重複や確定駅の阻害を避ける。

この処理はホーム縁から線路を決める条件を緩めない。寄居のように複数事業者でホームが一致する場合は、勝手に東武へ限定せず駅を保持する。
