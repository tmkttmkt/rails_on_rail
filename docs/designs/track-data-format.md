# Design: 鉄路データの形式と境界

## 決定

- 編集用原本はYAMLとする。
- YAMLのキーは英語camelCase、列挙値と永続IDは英小文字のkebab-caseとする。名称・説明・コメントは日本語で記述する。
- YAMLはJSON互換のデータ型へ限定する。
- 実行時JSONは必要になった時点でYAMLから生成する。
- 構造検証にはJSON Schemaを使用する。
- 電化設備のうち架線・第三軌条・電気方式は鉄路へ含める。
- 変電所・き電区間は独立した電力設備とする。
- 信号・閉塞と列車保安装置は鉄路から分離する。
- 地図上の線路はセグメントとして扱い、線路規格、法的状態、敷設形態が変わる地点で分割する。
- 法的状態と物理的な敷設形態を別属性にする。
- 軌道状態を線路規格から分離し、軌道形状の健全度と軌道構造の健全度を連続値で保持する。
- メートルトンのキー接尾辞は短い`T`を使用し、他の量へ同じ接尾辞を流用しない。
- レール断面の`regionType`は使用地域の制約ではなく、規格系統の分類として扱う。
- 締結装置、枕木・支持構造、道床は軌道支持方式として一体化し、路盤は独立した構成要素とする。
- ワールド座標はメートル単位とし、曲線半径は線路形状から導出する。
- カントはカタログ値ではなく、建設後の線路セグメントが持つ設備状態とする。

## YAMLを選ぶ理由

規格データは人間とAIが繰り返し編集・レビューし、出典や未確定事項をコメントとして扱う。YAMLはJSONより記述量と差分が小さく、この用途に適する。

一方でアンカーや暗黙型は解釈差を生むため禁止する。YAMLを自由形式の設定言語として使わず、英語キーのコメント可能なJSON表現として使用する。

## JSONとの関係

JSONを手編集する第二の正本にはしない。ゲームロード時にJSONが有利と確認された場合だけ、次の一方向変換を導入する。

```text
YAML原本 → Schema・参照検証 → 生成JSON → ゲーム
```

## データ境界

```text
track
  ├─ 軌道構成
  └─ 線路沿いの集電設備

power-facilities
  └─ 地図上の電力供給設備

signaling
  └─ 信号・閉塞・列車検知・連動

train-protection
  └─ 地上・車上保安装置と互換性

legal
  └─ 法制度、違反、特例認可、取締方針
```

法的状態は車両、軌道、運行、事業者に横断的に作用するため、いずれかの設備カタログへ埋め込まず`data/legal/`へ分離する。実際の違法性、当局による発覚、発覚後の取締対応を別々の状態として扱う。黙認は違法なまま未処分、特例認可は条件内で合法とする。

特例認可は違反救済に限定しない。通常基準とは異なる安全確保方法を審査し、本線高速化、踏切存置、新技術試験、運行継続などを合法にする制度として扱う。特例制度は、免除対象だけでなく認可性能、適用範囲、代替安全対策、監視条件を定義できる構造とする。

## 移行

旧`docs/data/`は車両、電化、保安装置を線路プリセットへ混在させていたため、内容を移植せず削除する。旧調査文書は履歴として保持し、現在のデータ正本からは参照しない。

## 線路セグメントの境界

`TrackSegment`の内部では線路規格、法的状態、敷設形態を一定とする。専用部分と併用軌道が切り替わる地点ではセグメントを分割する。

法制度上の分類だけから物理状態を推定しない。例えば軌道法に基づく区間であっても、道路交通と共用する区間と専用の線路敷を通る区間を別々に表現できるようにする。

一時的な速度制限、工事、災害、保守状態は線路の恒常的な同一性とは寿命が異なるため、セグメントの必須分割条件から除外し、将来の区間指定データへ分離する。

## 軌道状態と動的荷重

速度に応じた動的増幅を用いて、列車の静的軸重から軌道へ作用する動的軸重を求める。軌道側の限界は、レール、軌道支持方式、路盤など各構成要素の耐荷重の最小値を基礎とする。

軌道状態による影響は二重に区別する。軌道形状の劣化は作用する動的荷重を増加させ、軌道構造の劣化は耐えられる動的荷重を低下させる。両者を一つの状態段階へまとめない。

状態値は`0.0`から`1.0`までの連続値とし、画面上の状態名は表示時に導出する。動的増幅式と状態補正式は出典と適用範囲を確認してから計算モデルとして定義する。

## 水平線形との境界

制御点から生成される線路形状を正本とし、局所曲線半径と最小曲線半径は再計算可能な派生値として扱う。カントは形状から毎回導出する値ではなく、建設時に決定され、その後は改修されるまで残る設備状態である。

自由曲線、複線ごとの半径、カント、曲線による速度制約の詳細は[`track-horizontal-alignment.md`](track-horizontal-alignment.md)に定める。
