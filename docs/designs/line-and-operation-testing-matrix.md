# Design: 路線・系統・経路・運行・運用のテストマトリクス

## 単体テスト

| ID | 対象 | 確認内容 |
|---|---|---|
| UT-SYS-01 | 系統 | 親路線必須、名称・略称・色・説明・表示順の保存 |
| UT-SYS-02 | 系統 | 色未指定時の親路線色導出 |
| UT-ROUTE-01 | 経路 | 地点順、方向、legs、区間が正常保存される |
| UT-ROUTE-02 | 経路 | 系統の親路線と区間路線の不一致を拒否 |
| UT-ROUTE-03 | 経路 | 区間の空白・逆転・不正重複を拒否 |
| UT-ROUTE-04 | 経路 | 垂直接続・非接線接続を経路として採用しない |
| UT-OP-01 | 運行 | 経路参照と日付条件、着発時刻を保存 |
| UT-OP-02 | 運行 | 0、1、2日以上の `dayOffset` を含む時刻順検証 |
| UT-DUTY-01 | 運用 | 複数運行の順序と編成割り当てを保存 |
| UT-DUTY-02 | 運用 | 複数日運行の時刻重複と、駅・番線不一致を検出 |
| UT-DUTY-03 | 運用 | 同一編成の競合割り当てを拒否 |
| UT-DUTY-04 | 運用実施 | 通常編成を日別の編成指定で上書きできる |

## 統合テスト

| ID | シナリオ | 期待結果 |
|---|---|---|
| IT-DIRECT-01 | A線A系統からB線B系統へ直通する経路 | 区間順と物理経路を維持して保存・再読込できる |
| IT-OP-01 | 同一経路から朝夕2運行を作る | 経路を共有し時刻だけ独立する |
| IT-DUTY-01 | 往路・復路運行を1運用へ登録 | 時刻と終始発条件が連続すれば編成を割り当てられる |
| IT-DUTY-02 | 3日間にまたがる運行と運用 | 日時順を維持し、保存・再読込・発車判定ができる |
| IT-DISPATCH-01 | 適合配置から発車 | 実行状態が reserved、operating、completed と遷移する |
| IT-DISPATCH-02 | 駅・線路・向きの不一致 | 理由付きで発車を拒否する |
| IT-GUARD-01 | 経路参照中の線路削除 | 参照元を示して拒否する |

## 永続化テスト

- v10の系統・方向・経路・予約をv11の系統・経路・運行・運用・実行状態へ決定論的に移行する。
- 複数路線所属や区間境界を一意に復元できないデータは警告として列挙する。
- v11の往復シリアライズで全ID、順序、参照が一致する。
- 壊れた参照、時刻順、区間、施設参照を含むロードは原子的に失敗する。

## UI受入

1. 路線と系統の表示属性を編集する。
2. 2路線を跨ぐ片方向経路を作成し、反対方向を別経路として作る。
3. 各経路から日時付き運行を作成する。
4. 複数運行を運用へ並べ、配置編成を割り当てる。
5. 適合候補と不適合理由を車両画面で確認して発車する。

ブラウザ検証は主要チェックポイント完了時にまとめて行い、小変更ごとには実施しない。
