# 近似再現の線路・編成基盤

上位目標は実用的なゲーム完成であり、東上線固有の数値や時刻表をシミュレーションへ埋め込まない。既存の線路、Station、Route、編成テンプレートを組み合わせる。駅順・入出力・試験編成はYAML、幾何と停車範囲は既存OSMセーブ、時刻表は後続の別部品とする。

段階2では短編成を採用する。200mへの全駅拡張は元データの用途を変え、必要以上の修復を伴うため初回に要求しない。20mが収まることは10両適合の証明ではない。留置拒否は警告として保持し、旅客停車や走行の可否と混同しない。

経路探索の既存API `findStationRoute` に任意のfrom/to端点制約を追加する。指定がある場合は駅の該当線路・範囲を検証し、距離を探索グラフへ加える。駅IDのみの呼出しは既存挙動を維持する。`findPhysicalRouteBetweenStops` は受け取った指定を転送する。二つのRoute構築入口とも、明示された停車点ID・indexが指定線路と一致しない場合は拒否する。

有向の連続経路候補は `findYardPath` を使用して検査する。2026-11-11の修正で有向探索を `directedPath.ts` へ抽出し、営業経路にも共用して駅間の暗黙反転を防いだ。生成時には保存する営業経路の区間列も照合する。駅での折返し条件、上下分離、運転時の占有・競合予約は後続で扱う。候補経路の成立を全日運転の成立とは扱わない。
