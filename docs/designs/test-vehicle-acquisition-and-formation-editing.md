# Design: 資金なしテスト車丷取得と編成組換え

## 目的

経済やメーカー販売を実装する前に、カタログ設計から保有車両を作り、個別車両または完成編成として取得し、編成を組み替えられる最小の車両管理ループを成立させる。

## 用語

- 車両設計: YAMLカタログにあるメーカー設計。所有物ではない。
- 運行会社形式: 車両設計を会社内で扱う名称・仕様参照。
- 車両個体: 固有IDと事業者番号を持つ所有物。
- 完成編成テンプレート: 複数の車両設計、順序、向きを定義する取得用データ。
- 編成: 所有車両個体の順序付き集合。
- 未所属車両: どの編成にも属さない保有車両。

## テストモード取得

取得操作は価格、資金、納期を持たず即時完了する。ただし将来の購入処理と意味を混同しないため、UI表示は「テスト取得」、命令は`acquire`とする。`purchase`という名前で価格0を埋め込まない。

### 個別車丷取得

入力:

- `designId`
- 任意の事業者番号

処理:

1. 設計の存在確認
2. 対応する運行会社形式を検索
3. なければ既定名で自動生成
4. 車両IDと番号を採番
5. 未所属車両として追加

同一設計を複数取得できる。事業者番号未指定時は会社形式ごとの次番号を採番する。

### 完成編成取得

テンプレート例:

```yaml
id: test-passenger-formation-3car
name: テスト旅客3両編成
vehicles:
  - designId: test-virtual-locomotive
    orientation: forward
  - designId: test-coach
    orientation: forward
  - designId: test-coach
    orientation: forward
```

取得は一トランザクションで実行する。

1. 全設計とテンプレート構造を検証
2. 全車両ID・番号と編成IDを仮採番
3. 隣接端の連結器を検証
4. ブレーキ警告を計算
5. 全項目が成功した場合だけ状態へ追加

途中失敗時に車両だけ残してはならない。

## 仮想機関車

今回のテスト用機関車は、機回しや運転台方向を要求しない。これは車両方向を削除する意味ではない。

- 車両の`orientation`は連結端判定のため保持する。
- 仮想機関車設計へ`capabilities.bidirectionalOperationWithoutRunaround: true`相当を将来追加可能にする。
- 今回の発車可否はこの能力を要求せず、すべてのテスト編成を両方向運転可能とみなす。
- 実在機関車導入時にこの暫定規則を置換するTaskを必要とする。

## 編成編集操作

### 作成・改名・削除

- 空編成を作成できる。
- 名前は1〜80文字、空白のみ不可。
- 同名編成は許容し、IDで識別する。
- 車両を含む編成、配置・予約・運行中編成は削除不可。

### 車両追加

- 未所属車両だけを追加可能。
- 前または後へ追加する。
- `forward`または`reversed`を指定する。
- 隣接する一箇所の連結器を検証する。
- 追加後に編成全体のブレーキ警告を再計算する。

### 取り外し

- 対象車両を未所属へ戻す。
- 取り外し後に新しく隣接する二両の連結器も検証する。
- 取り外しで不適合が生じることは通常ないが、接続オーバーライド将来対応のため全体再検証する。
- 空編成になることを許す。ただし配置・予約・発車は不可。

### 並べ替え・反転

- 移動後の全隣接組を検証し、連結器不適合なら操作全体を拒否する。
- 車両反転も同様に全体を再検証する。
- ブレーキ不連続は操作を許可して警告更新する。

### 編集ロック

配置、予約、運行中編成は編集不可とする。配置解除後に編集する。これは物理的な入換を省略する今回の境界であり、将来の線路上入換機能とは別物である。

## 編成テンプレートの初期セット

最低限、次をデータとして定義する。

- 仮想機関車1両
- 仮想機関車＋客車2両
- 仮想機関車＋貨車3両
- 双方向動力車2両

既存draft車両を利用できる場合は重複設計を追加しない。不足する仮想機関車だけを明示的なtest IDで追加する。実在値であるかのような名称を使わない。

## 警告と拒否

| 状態 | 結果 |
|---|---|
| 連結器非互換 | 操作拒否 |
| 貫通ブレーキ共通方式なし | 操作許可、警告 |
| 車両が別編成所属 | 操作拒否 |
| 編成が編集ロック中 | 操作拒否 |
| 空編成 | 保存可、配置・発車不可 |
| 同一車両番号 | 操作拒否 |

## 将来の経済への境界

取得処理を次の三段へ分離可能にする。

```text
提供条件の生成 → 取引承認 → 所有実体の生成
```

今回は最後の「所有実体の生成」だけを直接呼ぶ。価格0の取引履歴は作らない。

## 検証

- 同一設計を複数取得してIDと番号が重複しない。
- 完成編成取得失敗時に状態が変わらない。
- 全編集操作で入力状態を破壊しない。
- 連結器拒否とブレーキ警告を向き変更後も正しく計算する。
- 配置・予約・運行中の全編集命令を拒否する。
