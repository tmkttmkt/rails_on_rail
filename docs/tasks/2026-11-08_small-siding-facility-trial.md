# 小さな側線で用途指定・車両配置・本線往復を成立させる

目的: 車庫・留置線・引上げ線・保守用側線を用途と停車可能範囲に分離し、小施設から運用を確認する。
範囲: 共通の施設用途設定、側線からの施設登録、試験用自走保守車、既存fleet/yardを使う一往復、操作UIと東上線の実配線検証。
制約: 現地用途を捏造しない。未知の側線は用途未確認とする。本線のダイヤ・信号・実車性能・自動車庫分類は対象外。既存セーブと未コミット作業は保持する。
完了条件: 側線選択→用途設定→安全な範囲確認→車両配置→本線へ出て戻る流れをUIで実行し、シミュレーションでも占有位置の往復を検証する。
検証: 用途と旅客駅の区別、支障範囲・不足長・誤軌間・重複配置の拒否、保存再読込、途中保存からの完走、元OSM線形不変、全テスト・ビルド・ブラウザー確認。
関連: [車庫マップ](../features/tojo-depot-map.md)、[既存入換](../features/yard-operations.md)。

## 実装と検証結果

[設計](../designs/small-siding-facilities.md) / [現在仕様と操作](../features/siding-facilities.md)。用途・施設範囲・試験車・4工程の本線往復を共通MapCommandで実装した。専用の巨大な操車場機能は追加せず既存fleet/yardを使用する。

`npm test`: 33ファイル265テスト成功。`npm run build`: 成功。`npm run verify:siding-trial`: 上福岡の元配線で182秒の往復、本線占有、途中保存再読込、側線の元位置・向きへ復帰、fleetと線形・接続不変を確認。検証は実行開始前の試験セーブを別出力する。

ブラウザーで元の車庫マップの上福岡施設を選び、用途未確認→保守用側線→試験車配置→往復開始→60×→本線往復完了を確認した。画面操作の確認は4/5: 操作と完了確認はできるが、車体・ラベルが重なりやすく、現実の保守作業や営業運転との混在は範囲外。人間による操作感・仕様採否は未確認のためreview。

残作業: 本線運転との競合・信号、検修機能、電化条件、実在保守車データ、複数車両や他施設での運用。コミットは行っていない。
