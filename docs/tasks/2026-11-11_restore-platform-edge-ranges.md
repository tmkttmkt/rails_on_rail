# Task: 旅客ホーム長を合成180 mからホーム端実測へ戻す

## 目的・背景

2026-11-11のユーザー指摘による。領域マップの旅客停車範囲113件のうち99件がちょうど180.00 mだった。これは実測ではなく、[駅範囲の遠隔誤生成修復](2026-11-07_repair-imported-station-ranges.md)で使った`restoreStationStopPoint`の既定値`halfLengthM = 90`がそのまま残った値である。修復の目的は位置の復元であり、ホーム端データは使っていない。

180 mは東上線のどの編成にも対応しない。本線は10両（20 m車×10＝200 m）、越生線と小川町以北は4両（80 m）である。一律180 mは越生線側で長すぎ、本線側で短すぎる。

[実装順序](../planning/tojo-holiday-implementation.md)の「既存の旅客範囲が最大約180 mである点は、長い編成を採用する前に解消または根拠付きで扱う」という制約は、実在の制約ではなくこの既定値だった。

`saves/osm-tojo-import-regression.json`（取込方針`platform-edge-local-operator-no-fallback`）にはOSMホーム端由来の実測範囲があり、180 mの区間は1件もない。ただし[ホーム対応修正Task](2026-11-08_fix-osm-passenger-platform-matching.md)の判断どおり、この取込は線路が欠損しており、公式図と照合した既存マップを上書きしてはならない。

## 責任範囲

- 線路集合は現行chain（公式図照合済み）を維持し、**長さだけ**をホーム端実測へ差し替える。
- 同一の駅・同一の線路に実測がある停車範囲だけを移植する。
- 実測がない範囲は推測で埋めず、現状値のまま残して件数と値を記録する。
- 車庫マップ・領域マップ・短編成試験セーブを再生成する。

## 対象外

- 線路・分岐・転てつ器の幾何変更。
- 旅客駅の線路集合の変更（`passengerTrackOverrides`と公式図照合はそのまま使う）。
- 欠損駅（武州長瀬・西大家・寄居）の範囲を新たに作ること。
- 20 m車・10両編成テンプレートの追加。長編成を実際に走らせる検証。
- 越生線・小川町以北の運転対象化。

## 完了条件

- [x] 領域マップの旅客停車範囲に、合成値由来のちょうど180.00 mが残らない。
- [x] 対象33駅（池袋〜小川町）で、実測のある範囲が実測値になっている。
- [x] 実測のない範囲の件数・駅・線路・現状値が報告に残る。
- [x] 線路・分岐・転てつ器が入力と一致する。旅客駅の線路数が公式図照合を通る。
- [x] 型検査、全テスト、ビルド、車庫・領域・試験の再生成が成功する。

## 方針・判断

- 移植は車庫マップ生成の**前段**で行う。`passengerTrackOverrides`による線路除外と`tojo-platform-reference.json`との線路数照合を、従来どおり後段で効かせる。
- 元の取込スナップショット`saves/osm-tobu-tojo.json`は変更せず、別出力`saves/osm-tobu-tojo-measured.json`を作る。`tojo-depots.yaml`の`source`と`sourceSha256`をそちらへ向ける。スナップショット固定の検査は維持する。
- 2つの入力は線路317本・分岐420箇所が完全一致であることを確認済み。移植前に同一性を再検査し、違えば中止する。
- 幾何が同一なので、距離と端点座標はホーム端版の値をそのまま使う。停車地点のIDと`direction`は現行chainのものを維持し、参照を壊さない。
- ホーム端版に対応する線路がない範囲は、長さを変えない。180 mが残る場合も「未実測の既定値」として報告へ残し、実測値と混ざることを明示する。

- 再生成した領域マップで180.00 mの件数を数える。

## 作業結果

[restore-platform-edge-ranges.ts](../../scripts/restore-platform-edge-ranges.ts)を追加した。現行スナップショットとホーム端セーブを受け取り、同一の駅名・同一の線路に実測がある停車範囲だけ距離と端点座標を差し替える。停車地点のIDと`direction`は維持する。`npm run restore:platform-edge-ranges`で実行できる。

実行前に次を検査し、違えば中止する。入力が運転前・領域分割前であること、線路・分岐・転てつ器が両入力で完全一致すること、実測範囲が線路長に収まること、同名の旅客駅がないこと。実行後に駅・停車地点の構成（ID・線路・方向）と構内停車場が入力と一致することを再検査する。

元スナップショット`saves/osm-tobu-tojo.json`は変更していない。派生物`saves/osm-tobu-tojo-measured.json`を作り、[tojo-depots.yaml](../../data/maps/tojo-depots.yaml)の`source`と`sourceSha256`をそちらへ向けた。スナップショット固定の検査は従来どおり効いている。

移植結果は139範囲のうち108範囲。残る31範囲に実測がない。うち18範囲が合成180 mだった。ただし車庫マップ生成時の`passengerTrackOverrides`が壊れた範囲（坂戸の5 m断片、朝霞13.5 m、新河岸40.2 mなど）を従来どおり除外するため、**最終の領域マップで未実測として残るのは7範囲**である。和光市track-1/track-10、中板橋track-50、武州長瀬2線、西大家track-5、寄居track-2。いずれも180.00 mのままで、実測値と混在することを報告へ残した。

車庫・領域・短編成試験を再生成した。領域は56から54へ減った。ホーム長が実測へ伸びてホームの占有が増え、成増構内側線と小川町留置線で各1線群が40 m未満となり除外された。実際にホームが占める範囲なので、区間を作らない方が正しい。

## 検証結果

- `npx tsc` 成功。`npx vitest run` 35ファイル279テスト成功。ビルド成功（既存の500 kB超警告あり）。
- 移植報告`saves/osm-tobu-tojo-measured.json.platform-edge.report`で、幾何同一・駅構成不変・構内停車場不変がいずれもtrue、移植108・未実測31・合成180m残18を確認した。移植後の長さは82.8〜247.0 m。
- `npm run generate:tojo-depots` 成功。`tojo-platform-reference.json`との旅客線路数照合を通過した。
- `npm run generate:tojo-areas` 成功。12グループ・54領域、全12グループで未所属区間0・他グループ所有0。
- `npm run generate:tojo-trial` 成功。33駅・上下64区間の有向探索一致、保存再開の整合を確認した。
- 領域マップの旅客停車範囲113件のうち、ちょうど180.00 mは113件から**7件**へ減った。200 m以上は71件。最短82.8 m・最長247.1 m。
- 対象33駅のうち**31駅が200 m以上の範囲を持つ**。越生線は82.8〜100.8 m、小川町以北は91.1〜154.8 mとなり、4両相当の長さになった。

## 未確認事項・残作業

- 池袋（最長180.9 m）と北池袋（最長199.6 m）は200 mに届かない。これは合成値ではなくOSMホーム端データ自体の値であり、ホームwayが実際のホーム全長を覆っていない可能性がある。原因未調査。長編成を走らせる前に扱いを決める必要がある。
- 未実測の7範囲は180.00 mのまま残る。和光市track-1/track-10は本線の通過線で対象区間内にあり、200 m編成を置けない。公式図では和光市は4線すべてがホームに面するため、ホーム端データの欠損である。中板橋track-50も同様。
- 川越市の247.1 mはホーム端由来だが、他駅より30 m以上長い。ホームwayの結合誤りの可能性があり未検証である。
- 実測はOSMホームwayの形状であり、現地実測や東武公式の番線有効長と照合したものではない。
- 20 m車の形式データと10両編成テンプレートは未追加。200 m編成を実際に配置・走行させた検証は行っていない。試験編成は従来の20 m（10 m車2両）である。
- 越生線・小川町以北は運転対象外のまま。長さが4両相当になっただけで、運転の対象化はしていない。
- 画面での確認は未実施。

## 引き継ぎ

人間確認の手順。

1. `/?map=tojo-areas`を開き、ホーム範囲の長さが駅ごとに違って見えることを確認する。従来は全駅同じ長さだった。
2. 越生線（越生・東毛呂・武州唐沢・川角）と本線の駅でホーム長の差が見えることを確認する。
3. `/?map=tojo-trial`で短編成試験が従来どおり動くことを確認する。

再生成の順序は `restore:platform-edge-ranges` → `generate:tojo-depots` → `generate:tojo-areas` → `generate:tojo-trial`。生成物はODbL継承のため`.gitignore`対象で、正本は設定YAMLと生成スクリプトである。
