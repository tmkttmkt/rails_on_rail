# Task: 法的状態データ領域の定義

## 目的・背景

車両、軌道、運行、事業者に共通する法制度、違反、黙認、特例認可を、物理性能から分離して定義する`data/legal/`を作る。

## 責任範囲

- 法的状態データの責務と境界
- 法制度、違反種類、特例認可制度、取締方針の初期カタログ
- 実際の違反事例と取締状態を保存データで扱う方針
- データ索引と設計文書の更新

## 対象外

- 特定国・時代の実在法令の確定
- 違反発覚確率と処分計算の実装
- 車両データと事業者データ
- UI

## 完了条件

- [x] `data/legal/`のREADMEが責務を説明している
- [x] 4種類の初期カタログが存在する
- [x] 未発覚、黙認、特例認可が区別されている
- [x] YAML構文とID重複が検証されている

## 検証方法

- 全YAMLの重複キーを含む構文確認
- カタログ内IDの一意性確認
- `git diff --check`

## 作業結果

- `data/legal/`へ法制度、違反種類、特例認可制度、取締方針の4カタログを作成した。
- 未発覚、発覚、黙認、正式特例、処分を別状態としてREADMEへ定義した。
- 廃線危機路線向け特例と、末端路線で地方裁量を強くする取締方針のdraftを追加した。
- 特例認可を違反救済に限定せず、本線高速化、踏切存置、新技術試験を可能にする前向きな認可制度へ拡張した。
- 実際の違反事例と認可は、カタログではなく保存データへ記録する方針とした。

## 検証結果

- `data/`以下の全YAMLを重複キー検査付きで構文確認し、すべて成功した。
- 各カタログのID重複なし。
- 特例制度から法制度・違反種類への参照切れなし。
- `git diff --check`: 問題なし。

## 未確認事項・残作業

- 特定国・年代の法制度は未調査。
- 発覚危険度、黙認判断、特例審査、処分の計算は未実装。
- 車両形式・個体データとの接続は車両データ作成時に行う。
