# Task: 駅グループを地図に表示し、施設タブの自動選択をやめる

## 目的・背景

2026-11-11のユーザー指摘による。[建設と施設の操作を分離する](2026-11-10_facility-navigation.md)の`review`中に、施設操作の操作感へ二点の不満が示された。

1. 駅グループが地図に表示されない。普段は駅グループとして見え、拡大したら所属する駅部品になるべきである。
2. 施設タブを開いた時点で特定の駅グループの編集になるのはおかしい。

現状の原因はコードで次を確認した。

- `showStationAreas: appMode === "facility"`（[main.ts](../../src/main.ts)）のため、施設タブ以外ではグループ・領域を描画しない。
- `visibleAreas`（[renderer.ts](../../src/ui/renderer.ts)）が選択中グループだけへ絞り、下記の自動選択と合わさって常に1グループ分しか描かれない。
- ズームによる出し分けがなく、逆に領域所属駅のマーカーを施設タブで常に抑止するため、拡大しても駅部品へ戻らない。
- `appMode === "facility"`で`selectedStationComplexId`へ`state.stationComplexes[0].id`を自動代入し、[stationComplexPanel.ts](../../src/ui/stationComplexPanel.ts)も`?? state.stationComplexes[0]`へフォールバックするため、開くと必ずグループ1の編集になる。

## 責任範囲

- グループの地図表示を全モードへ追加し、ズームに応じてグループ表示と所属駅部品を切り替える。
- 施設タブをグループ未選択で開き、左パネルをグループ一覧にする。
- 地図上の折りたたみグループをクリックして選択・編集へ入れるようにする。
- 既存Feature・Designの表示規定を今回の挙動へ更新する。
- 2026-11-11の追加指摘により、地図データのグループ区分を設備種別で分け、通常運行の設備と車庫・保守系を同じグループへ入れない。

## 対象外

- シミュレーション、保存形式、領域の分割・用途・名称の編集機能そのもの。
- 施設の新設や試験車走行が建設タブ側にある構成の変更。
- 名称変更ボタンやEnter確定など、今回指摘されていない他の操作感。
- 用途領域の色面・番号を施設タブ以外へ常設すること。
- 領域の用途判定そのものの再調査、現地の正式用途・番線の確定。グループ区分はゲーム上の仮区分のまま扱う。

## 完了条件

- [x] 地図・建設など施設タブ以外でも、縮小時にグループが名前付きの一つの部品として見える。
- [x] 拡大するとグループ表示が所属する駅部品へ切り替わる。グループに属さない停車場は従来どおり常に駅部品として見える。
- [x] 切替はグループごとに判定し、大きな構内と小さな側線群が同じ倍率で切り替わらない。
- [x] 施設タブを開いた直後はどのグループも選択されず、全グループが地図に見える。
- [x] グループを地図のクリックまたは一覧から選ぶと、従来の領域編集へ入れる。
- [x] どのグループも、通常運行の設備と車庫・検修・保守の設備を同時に含まない。
- [x] 旅客ホームはグループへ入らず、独立した駅として残る。
- [x] 型検査、全テスト、ビルドが成功する。

## 方針・判断

- 折りたたみ判定は全体一律のズーム閾値ではなく、**グループごとの画面上の広がり**で決める。領域点群の外接矩形の長辺（m）× `camera.zoom`（px/m）が閾値を下回ったら折りたたむ。一律閾値では約600 mの川越市構内と約200 mの側線群が同じ倍率で切り替わり、「拡大したら部品になる」感覚と合わない。
- 閾値は描画側の表示判断として`renderer.ts`へ置く。既存の`drawTrack`が`camera.zoom`で枕木・簡略描画を切り替えているのと同じ階層に揃え、シミュレーションへ表示閾値を持ち込まない。
- 外接矩形の算出は`stationAreas.ts`の純粋な幾何関数とし、カメラを引数に取らない。描画と当たり判定の両方が同じ判定を使う。
- グループ表示は全モードへ出す。折りたたみ時は所属駅のマーカーを抑止して置き換えるため、情報量は増えない。用途領域の色面・番号は従来どおり施設タブだけに保つ。
- 「駅部品」は所属停車場のマーカーと名称（既存の`drawStation`）と解釈する。領域の色面の意味ではない。

## 作業結果

グループの外接矩形を`stationComplexBounds`として[stationAreas.ts](../../src/simulation/stationAreas.ts)へ追加した。カメラを引数に取らない純粋な幾何関数とし、表示閾値`COMPLEX_EXPAND_PX = 140`と`collapsedStationComplexes`は[renderer.ts](../../src/ui/renderer.ts)へ置いた。描画と地図の当たり判定が同じ判定を共有する。

[renderer.ts](../../src/ui/renderer.ts)では、折りたたみ中のグループを名称と領域数つきの二重枠で描き、その所属停車場のマーカーを抑止する。展開したら従来の駅部品へ戻す。グループ表示は`showStationAreas`に依存させず全モードで描く。用途領域の色面・番号は従来どおり施設タブだけで描き、折りたたみ中のグループでは点にしかならないため描かない。

領域番号は所属グループ内の順で描くよう変更した。従来は可視領域の通し番号で、1グループだけが見える前提に依存していた。未選択で全グループが見える状態では一覧の番号と合わなくなるため修正した。

施設タブの自動選択を撤去した。[main.ts](../../src/main.ts)は消えたグループの選択解除だけを行う。[stationComplexPanel.ts](../../src/ui/stationComplexPanel.ts)は未選択時にグループ一覧（領域数・停車区間数つき）を表示し、`?? state.stationComplexes[0]`のフォールバックをやめた。編集画面には「グループ一覧へ戻る」を追加し、`select`はnullを受け取れるようにした。

地図のクリックで折りたたみ中のグループを選択できるようにした。`focusStationComplex`に視点を動かさない経路を追加し、地図で選んだだけではカメラが飛ばないようにした。視点移動は一覧と「構内全体を見る」に残した。

施設タブで別グループを選択中でも、他グループの駅部品を消さないよう抑止条件を変更した。従来は「領域に関連付く停車場」すべてを抑止していたため、色面を描いていないグループの駅部品まで消えていた。実際に色面・番号を描いている領域の停車場だけを置き換える。

「駅部品」は所属停車場のマーカーと名称（`drawStation`）と解釈した。施設タブ内では従来設計どおり領域の色面・番号が駅部品の役割を担うため、施設タブでの置き換えは維持した。

### 地図データのグループ区分（2026-11-11の追加指摘）

指摘前は9グループ中8グループが旅客ホーム領域と車庫・留置・検修領域を同居させていた。川越市だけはホームを除外していたが、保守用側線・引上げ線・旧工場作業線を1グループへまとめていた。

[tojo-station-areas.yaml](../../data/maps/tojo-station-areas.yaml)と[generate-tojo-station-areas.ts](../../scripts/generate-tojo-station-areas.ts)を変更し、生成時の区分を次のようにした。

- 旅客ホーム領域の生成をやめた。旅客駅は従来どおりStationとして残り、グループへ所属しない。46駅は不変である。
- グループ名を駅名基準から設備基準へ変更した（例「下板橋駅・留置施設」→「下板橋留置線」）。
- 森林公園を「森林公園検修区」と「森林公園駅構内側線」へ分けた。
- 川越市を「川越市駅構内側線」（待機線・引上げ線）、「川越市北側保守用側線」、「川越市旧工場側構内」（留置線群・作業線群）へ分けた。残余の分岐区間は北側を保守側、南側を旧工場側へ所属させた。
- 本線接続部の±45 m範囲から旅客ホーム範囲を切り落とし、分岐接続通路がホーム範囲を所有しないようにした。
- 分岐接続通路の名称を駅名基準からグループ名基準へ変更した。同じ駅に複数グループが並ぶため、駅名基準では名称が重複する。

`stabling`は場所によって運行側（川越市駅西側待機線、成増構内側線、森林公園駅構内側線）と車庫側（下板橋・上福岡・小川町の留置線、旧工場側西留置線群）の両方に現れる。役割名ではなく設備の位置と用途で所属を決めた。

生成結果は9グループ・63領域から12グループ・56領域になった。`platform`役割の領域は0件である。

## 未確認事項・残作業

- 画面での見た目と操作感は人間確認待ち。閾値140 pxは根拠のある実測値ではなく、既存の`drawTrack`の倍率判断に揃えた初期値である。実際の見え方で調整が必要になる可能性がある。
- 折りたたみと展開の間にヒステリシスを入れていない。閾値付近でズームを往復すると表示が切り替わり続ける。
- グループ記号は外接矩形の中心へ置く。L字型など中心が線路から外れる構内では、記号が線路のない位置に出る。
- 施設タブ以外でグループを選択した場合、記号が強調されるだけで`#selection`には情報が出ない。
- 今回の指摘のうち、施設の新設と試験車走行が建設タブ側にある構成、名称変更ボタンの手数は対象外として残した。
- グループ区分は設備種別による整理であり、現地の正式用途・番線を確定したものではない。「志木留置・引上げ線」は元施設区分のまま留置と引上げを1領域に含んでおり、未分離である。
- 川越市の残余分岐区間を北＝保守側・南＝旧工場側へ所属させたのは幾何上の割り当てで、実際の入換経路で確認したものではない。
- `/?map=tojo-areas` の`?focus=`なし表示を全グループ表示へ変更した。既存の`?focus=`指定は従来どおり選択・移動する。
- 再生成した`saves/osm-tobu-tojo-areas.json`を使う既存の別セーブや画面確認は、旧グループ名・旧ID（`complex-kawagoeshi`など）を参照していると一致しない。

## 引き継ぎ

人間確認の手順は次のとおり。

1. `/?map=tojo-areas` を開く。初期表示は「施設」タブではないため、まず全体を縮小して9グループが名前つきの部品として見えることを確認する。
2. 一つのグループへ拡大し、所属する駅部品へ切り替わることを確認する。小川町などの小さな留置施設と川越市構内で、切り替わる倍率が別であることを確認する。
3. 「施設」タブを開き、特定グループの編集にならず一覧が出ることを確認する。
4. 一覧からグループを選び、従来の領域編集（色面・番号・分割）が従来どおり使えることと、「グループ一覧へ戻る」で戻れることを確認する。
5. 縮小してグループ記号を地図上でクリックし、視点が飛ばずに選択されることを確認する。
