# 構内を用途領域に分割し車両基地グループへまとめる

依頼: 車両を動かす試験より先に、川越市の例のような構内全体を広義の駅として分割・グループ化する。
目的: 構内・車両基地グループ→用途領域→停車可能区間の階層を作る。線路全体でなく同一線路内の区間も分割する。
範囲: 共通データ・命令・保存v15、領域と通路の区別、重複と参照の検証、東上線マップへの適用、地図の面表示と階層選択。川越市を重点的に区分し、既存の他施設も上位グループへまとめる。
制約: 線形と接続を捏造・変更しない。用途設定と現地用途の確証を分ける。咽喉部・通路を留置可能区間としない。実走試験や自動車庫運用の追加は行わない。
完了条件: 川越市の旅客・留置・引上げ・旧工場側線群・接続通路が別領域として表示・選択でき、親グループで全体を扱える。保存往復・範囲重複拒否・分岐支障・全テスト・ビルド・画面確認を実施する。
関連: [従来の車庫マップ](../features/tojo-depot-map.md)、[ユーザー意図を取り違えた小側線試験](2026-11-08_small-siding-facility-trial.md)。

## 結果と検証

[現在仕様](../features/station-complex-areas.md) / [設計](../designs/station-complex-areas.md)。構内グループ・用途領域・運用上の停車区間を分離し、区間での所有・同一線路分割・上位所属・保存v15・編集UI・面表示を実装した。既存東上線URLも領域版を優先する。小側線の車両往復を本件の成果として扱わない。

川越市9領域、全体9グループ65領域。全グループの指定範囲の未所属0、領域重複0。元線路・接続点・転てつ器・旅客駅の不変を生成中に検査する。`npm run generate:tojo-areas` 成功。34ファイル271テスト成功、ビルド成功（500 kB超のバンドル警告あり）。

ブラウザーで全体表示と個別選択、引上げ区間を90 m位置で二分割して9→10領域となること、親所属が維持されること、前側の停止区間が0になること、森林公園20領域への切替を確認した。元の生成データは変更せず、最後は川越市全体の初期区分へ戻す。見た目の評価は4/5: 階層と色面は読めるが、密集箇所の番号が近接することがある。最終的な区分の適否はユーザー確認待ち。

未確認: 仮区分の現地用途、旧工場側の進入経路、正式番線、信号・連動と実走。領域包絡は測量境界ではない。ユーザー提示の例に対応する構造を作ることが今回の範囲であり、現地設備の再稼働を保証しない。コミットは行っていない。

2026-11-09追記: 構内編集パネルは初期状態で閉じ、地図ツールバーから切り替える。 川越市の旅客ホームと旧2番（北側の142・160）を車両基地グループの対象外にする。旅客駅・既存の北側施設と線路は維持する。旧8番の名称は残余区間の仮分類であることが分かる表現にする。

再生成で川越市7領域、全体63領域を確認。旧2番の線路が残余領域に混入せず、元の配線・旅客駅が不変であることを確認した。

構内編集の開閉に合わせ、色面・番号も切り替える。型検査・ビルドと差分チェックが通過。人間による操作確認は、地図を開いて上部の「構内編集」で開閉する。
