# 営業経路の分岐点での暗黙反転を防ぐ

目的: ユーザー画像で指摘された、分岐器をあり得ない向きに渡る経路を修正する。

原因: `findStationRoute` は進行方向を持たないグラフと向きを無視した接線一致を使っていた。短編成試験では有向経路候補を検査しても、保存するRouteはこの別探索で生成していた。

範囲: 営業経路にも既存の有向探索を共用し、分岐内の暗黙反転を拒否する。試験マップを再生成して保存経路も検証する。UI表示で経路を隠す修正はしない。

設計: `findStationRoute` の停車線路・距離制約は維持し、各始終点について出発向き±1の `findYardPath` を調べ、到達可能な最短経路を採用する。線路幾何の軸比較は編集用途にも使うため変更しない。信号・占有制御は対象外。

完了条件: 分岐で逆向きに渡る不正な最短経路を回帰テストで拒否し、正しい向きの分岐通過と逆向き定義の線路を維持する。生成した上下64区間を有向探索の経路と照合する。

検証: 回帰・全テスト、型検査・ビルド、短編成試験再生成、元データ不変。外観は人間確認待ち。

## 結果

有向探索・接線計算・区間統合をデータカタログに依存しない `src/simulation/directedPath.ts` へ抽出し、営業と入換で共用した。`yard.ts` からの既存API再公開は維持する。編集用の接線軸比較は変更しない。最初にyardから直接importした方法ではVite設定の読込時にYAMLを巻き込んで起動できなかったため、純粋な経路モジュールへ分離して解消した。

回帰テストでは分岐器の背向側2本を直接渡る暗黙反転を両方向で拒否し、正当な進入・退出は維持する。線路の点列が逆順でも同じ判定になることを確認した。生成処理でも端点一致だけでなく、保存する各営業経路と有向探索の区間列を全64区間で照合するようにした。

- 関連2ファイル12テスト、全35ファイル277テスト成功。
- `tsc` 成功。別出力先 `node_modules/.direction-routing-build` の本番ビルド成功。既存500kB超警告あり。
- `npm run generate:tojo-trial` 成功。通常権限では既存生成物の更新がEPERMとなり、昇格して試験専用セーブ・レポートだけを再生成した。元入力・設備不変、保存再開の整合、全64区間の有向探索との一致を確認した。

確認手順: `/?map=tojo-trial` を再読込し、上下経路を選択して画像で指摘された箇所を再確認する。既存の別セーブに保存された旧Routeは自動修復しないため、経路の再作成が必要。画面上の同一箇所の目視は未実施。各駅間の方向は保証するが、駅での折返し許可や信号・競合制御は別課題である。
