# Task: 施設タブで駅グループと駅を詳しく調べ、編集できるようにする

## 目的・背景

2026-11-11のユーザー要望による。施設タブは[建設との分離](2026-11-10_facility-navigation.md)で領域編集を担うようになったが、駅グループと駅について調べられる情報が乏しく、編集できる項目も限られている。

現状で確認した不足点は次のとおり。

- 駅を選んでも右パネルは3行の要約だけで、停車地点の一覧が`線路ID · 180 m`を`Math.round`で丸めて並べるだけである。方向、最長・最短、どの編成長が入るか、所属グループ・領域が分からない。
- グループを選んでも「N用途領域を管理」しか出ない。役割の内訳、線路数、停車区間数、最長停止長、構内の広がりが分からない。
- 駅の編集は駅名変更だけである。`station.setKind`は命令として実装済みだがUIがない。
- `stationComplex.delete`と`stationArea.delete`も命令だけ存在し、UIからは到達できない。

## 責任範囲

- 施設タブで選択した駅の詳細（停車地点ごとの線路・長さ・方向、合計と最長最短、編成長の可否、所属グループ・領域、ホーム未確定理由）を表示する。
- 施設タブで選択したグループの詳細（役割内訳、線路数、停車区間数、最長停止長、構内の広がり）を表示する。
- 駅種別の変更を施設タブへ追加する。
- グループと領域の削除を施設タブへ追加する。既存の拒否条件はそのまま使う。

## 対象外

- 駅の新設、範囲の延長・統合・物理撤去。これらは建設に残す。
- 停車地点の距離・座標の直接編集。
- シミュレーション、保存形式、経路・運行・運用の変更。
- 編成長データの追加。判定は長さの比較だけで行い、車両データは増やさない。
- 検証用UIの追加。本番の操作パネルとして作る。

## 完了条件

- [x] 施設タブで駅を選ぶと、停車地点ごとの線路・長さ・方向と、最長・最短、編成長の可否、所属が分かる。
- [x] 施設タブでグループを選ぶと、役割内訳・線路数・停車区間数・最長停止長・広がりが分かる。
- [x] 施設タブで駅種別を変更できる。領域に属する停車場では従来どおり拒否され、理由が出る。
- [x] 施設タブでグループと領域を削除できる。子領域が残る親の削除と参照中の削除は従来どおり拒否される。
- [x] 型検査、全テスト、ビルドが成功する。

## 方針・判断

- 読み取り専用の詳細は右パネル`#selection`へ置く。ここは`updateUi`ごとに再構築されるため、入力欄や選択欄を置くと操作中に状態が失われる。表示だけに限る。
- 操作する項目は`#facility-panel`（駅・停車場）と左パネル`#complex-panel`（グループ・領域）へ置く。どちらも`dataset.signature`で再構築を抑えており、入力中の状態を保てる。
- 編成長の可否は長さの比較だけで示す。10両＝200 m、4両＝80 mは20 m車前提の表示用の目安であり、車両データから計算した値ではないことを画面に明示する。
- 削除は誤操作を避けるため`details`の中へ置く。確認ダイアログは既存UIの作法に合わせて使わず、命令側の拒否と結果メッセージで扱う。
- 既存の`stationComplexBounds`を広がりの表示へ再利用する。表示用に新しい幾何計算を増やさない。

- 人間確認: `/?map=tojo-areas`の施設タブで、駅・グループ・領域をそれぞれ選び、表示内容と編集・削除の動作を確認する。

## 作業結果

[main.ts](../../src/main.ts)へ`stationDetailHtml`と`stationComplexDetailHtml`を追加し、施設タブの右パネルを詳細表示へ差し替えた。

- 駅・停車場: 種別（旅客駅以外は施設用途も）、停車場ID、停車地点数、停車地点ごとの線路・長さ・方向の表、最長と最短、編成長の目安ごとに入る線数、所属グループと領域、ホーム未確定理由。
- グループ: 用途領域数、線路数、停車区間数、役割の内訳、最長の停止可能長、構内の広がり。広がりは[駅グループ表示Task](2026-11-11_show-station-groups-on-map.md)で追加した`stationComplexBounds`を再利用した。

編集は`#station-management`セクションを新設し、`renderStationManagement`で描画した。停車場の種別を`station.setKind`で変更できる。領域に属する停車場では選択欄を出さず、どの領域が種別を決めているかを示して領域編集へ誘導する。

[stationComplexPanel.ts](../../src/ui/stationComplexPanel.ts)へ領域の削除とグループの削除を追加した。どちらも`details`の中に置いた。グループの削除は領域が0件のときだけ表示する。

[style.css](../../src/style.css)へ詳細表の`.detail-table`と`.station-management`の外観を追加した。

### 実装中に直したこと

- 種別変更が拒否されたとき、種別が変わらないため署名も変わらず、選択欄が失敗した値のまま残っていた。拒否時は署名を消して再描画する。
- 領域削除の説明文を「関連付けた停車場は失われる」と書いていたが、実挙動は停車場と線路を保持する（`stationAreas.ts`の「領域の区分を解除しました（停車場・線路は保持）」）。文言を実挙動へ合わせた。

読み取り専用の詳細を右パネル、操作する項目を署名付きのパネルへ分けた。右パネルは`updateUi`ごとに再構築されるため、入力欄を置くと操作中に状態が失われる。

## 検証結果

- `npx tsc` 成功。

- `git diff --check` 成功。シミュレーション・保存形式・生成スクリプトは変更していない。

## 未確認事項・残作業

- 画面での表示・操作感は人間確認待ち。詳細表の行数が多い駅（和光検車区のような多線群の停車場）で右パネルがどこまで伸びるかは未確認である。
- 編成長の目安は10両200 m・6両120 m・4両80 mを表示用に固定した。20 m車前提の値で、車両データからの計算ではない。実在編成の長さを増やす場合は目安側も見直す必要がある。
- グループの削除は領域0件のときだけ到達できる。領域を持つグループを畳む操作（領域を別グループへ移してから削除する）は手順が分かれたままである。
- 駅の新設・延長・統合・物理撤去は建設タブに残している。今回の要望の範囲外として触っていない。
- 停車地点の距離・座標を画面から直接編集する手段は追加していない。

## 引き継ぎ

人間確認の手順。`/?map=tojo-areas`を開き施設タブへ移る。

1. グループ一覧からグループを選び、右パネルに役割内訳・線路数・停車区間数・最長停止長・広がりが出ることを確認する。
2. 地図で旅客駅を選び、停車地点の表に線路・長さ・方向が並び、編成長の可否が出ることを確認する。ホーム長を実測へ戻したので駅ごとに値が違う。
3. 領域に属する停車場（例: 下板橋留置線の領域）を選び、種別の選択欄が出ず領域編集への誘導が出ることを確認する。
4. 領域に属さない停車場で種別を変更し、反映されることを確認する。
5. 領域編集の「この領域を削除」で区分が解け、線路と停車場が残ることを確認する。その後そのグループが空になれば「このグループを削除」が出る。
