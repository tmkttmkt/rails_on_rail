# Task: OSMの鉄道データからマップを生成する

## 目的

OpenStreetMapの鉄道データを現行のマップモデルへ取り込み、実在の路線網と
構内配線からセーブファイルを生成できるようにする。

手作業で設計したマップが実物と異なるという評価が出発点であり、
[取り込み可能性の測定](../research/osm-railway-import-feasibility.md) で
障害が転てつ器の分岐側に絞られること、それ以外は清浄であることを確認済みである。
分岐側の生成は [転てつ器モデル](../designs/turnout-model.md) で導入した
`turnout.create` を使う。

## 責任範囲

- Overpass APIの応答JSONを入力として受け取る取り込みスクリプト
- 緯度経度から局所メートル座標への投影
- 分岐ノードでのway分割と線路・接続点の構築
- 3分岐以上のノードにおける転てつ器の再構成
- 取り込み結果のトポロジー診断レポート

## 対象外

- Overpass APIへの問い合わせそのもの（スクリプトはネットワークへ接続しない。
  取得手順を文書化し、応答JSONをファイルとして受け取る）
- **OSM由来のセーブファイルをリポジトリへ含めること**（ODbLの継承義務を避けるため、
  スクリプトのみをコミットし、マップは各自が手元で生成する方針を採った）
- 駅・プラットフォーム・信号・電化方式の取り込み
- 緩和曲線（クロソイド）の復元
- 番数の推定精度の作り込み（まず既定値で通す）

## 方針

| 課題 | 対応 |
|---|---|
| ネットワーク接続 | スクリプトはファイル入力のみ。取得コマンドはREADMEへ記載 |
| ODbL | 生成セーブはコミットしない。出力先の既定を `saves/` 外にはしないが、`.gitignore` へ登録する |
| 投影 | 範囲中心の緯度における正距円筒近似 |
| way分割 | 共有ノードでwayを分割し、分割片ごとに線路を作る |
| 直進側 | 最も直線に近い組を直進とみなして連鎖させる |
| 分岐側 | `turnout.create` で接線連続な分岐側を生成し、その終端へ残りのポリラインを接続する |

## 成果物

- `scripts/import-osm-map.ts`
- `.gitignore` への `saves/osm-*.json` の追加

実行方法:

```bash
# 1. Overpass APIから取得する（スクリプトはネットワークへ接続しない）
curl -A rails-on-rail/0.1 -H "Content-Type: text/plain; charset=utf-8"   --data '[out:json][timeout:180];way["railway"~"^(rail|narrow_gauge)$"](55.37,36.82,55.45,36.93);out body;>;out skel qt;'   https://overpass-api.de/api/interpreter -o osm.json

# 2. 取り込む
npx vite-node scripts/import-osm-map.ts osm.json saves/osm-bekasovo.json "ベカソヴォ (OSM)"
```

Overpass APIはUser-Agentがないと406を返す。Cyrillicを含むクエリは
UTF-8のファイルとして渡す（Windowsのシェル経由では文字化けする）。

## 処理の流れ

1. 投影（範囲中心の緯度における正距円筒近似）
2. ノード接続数を数え、2以外を「キーノード」（分岐・終端）とする
3. キーノード間のポリラインを「辺」として分解する
4. 各節点で最も直線に近い一対を直進とみなし、残りを分岐側とする
5. 直進で辺を連鎖させ「通し経路」にまとめる
6. 通し経路を1本の線路として敷設する（最長の経路から幅優先）
7. 分岐側は `turnout.create` で接線連続なスタブを生成し、その終端へ
   残りのポリラインを接続する。転てつ器の番数は実測の発散角から選ぶ

## 検証結果

ベカソヴォ周辺のOverpass応答（way 415本、node 2419）を取り込んだ結果。

| 項目 | 値 |
|---|---|
| 辺 | 793 |
| 通し経路 | 279 |
| キーノード | 540（うち分岐を持つ節点 471） |
| 生成した線路 | 550（通し経路279＋転てつ器スタブ271） |
| 生成した転てつ器 | 271（失敗8） |
| 接続成分 | 8（最大425本＝全体の77%） |
| 孤立線路 | 2 |
| **不正接続** | **0** |
| 曲線半径 | 最小4.9 m、5% 23.7 m、25% 129 m、中央145 m |
| 50 m未満の線路 | 68本（12%） |

- 生成セーブの `parseSaveFile`: 成功。
- `npm test`: 24ファイル、200テスト成功。
- `npm run build`: 成功。
- `saves/osm-*.json` が `.gitignore` で除外されることを確認。

## 未確認事項・残作業

- ブラウザで取り込んだマップを人間確認する。
- **線形の品質が未達**。50 m未満の半径が68本（12%）残る。主因は、分岐側を
  スタブへ取り付ける際に直線の接線許容（5度）へ収まらず `curve` へ退避した
  66本で、そこで円弧チェーンの発振が起きている。緩和曲線を含む正しい線形復元が
  本質的な解であり、未着手である。
- **閉路が閉じない**。接続先の経路がすでに敷設済みの場合（234件）に接続を
  作っていないため、接続成分が8つに分かれる。短絡線で閉じる処理が必要。
- 転てつ器の設置失敗8件の原因を特定していない。
- 駅・プラットフォーム・信号・電化方式・最高速度を取り込んでいない
  （軌間と速度は既定値で固定している）。
- 1地点でしか検証していない。
