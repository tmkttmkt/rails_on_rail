# Task: OSMの鉄道データからマップを生成する

## 目的

OpenStreetMapの鉄道データを現行のマップモデルへ取り込み、実在の路線網と
構内配線からセーブファイルを生成できるようにする。

手作業で設計したマップが実物と異なるという評価が出発点であり、
[取り込み可能性の測定](../research/osm-railway-import-feasibility.md) で
障害が転てつ器の分岐側に絞られること、それ以外は清浄であることを確認済みである。
分岐側の生成は [転てつ器モデル](../designs/turnout-model.md) で導入した
`turnout.create` を使う。

## 責任範囲

- Overpass APIの応答JSONを入力として受け取る取り込みスクリプト
- 緯度経度から局所メートル座標への投影
- 分岐ノードでのway分割と線路・接続点の構築
- 3分岐以上のノードにおける転てつ器の再構成
- 取り込み結果のトポロジー診断レポート

## 対象外

- Overpass APIへの問い合わせそのもの（スクリプトはネットワークへ接続しない。
  取得手順を文書化し、応答JSONをファイルとして受け取る）
- **OSM由来のセーブファイルをリポジトリへ含めること**（ODbLの継承義務を避けるため、
  スクリプトのみをコミットし、マップは各自が手元で生成する方針を採った）
- 駅・プラットフォーム・信号・電化方式の取り込み
- 緩和曲線（クロソイド）の復元
- 番数の推定精度の作り込み（まず既定値で通す）

## 方針

| 課題 | 対応 |
|---|---|
| ネットワーク接続 | スクリプトはファイル入力のみ。取得コマンドはREADMEへ記載 |
| ODbL | 生成セーブはコミットしない。出力先の既定を `saves/` 外にはしないが、`.gitignore` へ登録する |
| 投影 | 範囲中心の緯度における正距円筒近似 |
| way分割 | 共有ノードでwayを分割し、分割片ごとに線路を作る |
| 直進側 | 最も直線に近い組を直進とみなして連鎖させる |
| 分岐側 | `turnout.create` で接線連続な分岐側を生成し、その終端へ残りのポリラインを接続する |

## 成果物

- `scripts/import-osm-map.ts`
- `.gitignore` への `saves/osm-*.json` の追加

実行方法:

```bash
# 1. Overpass APIから取得する（スクリプトはネットワークへ接続しない）
curl -A rails-on-rail/0.1 -H "Content-Type: text/plain; charset=utf-8"   --data '[out:json][timeout:180];way["railway"~"^(rail|narrow_gauge)$"](55.37,36.82,55.45,36.93);out body;>;out skel qt;'   https://overpass-api.de/api/interpreter -o osm.json

# 2. 取り込む
npx vite-node scripts/import-osm-map.ts osm.json saves/osm-bekasovo.json "ベカソヴォ (OSM)"
```

Overpass APIはUser-Agentがないと406を返す。Cyrillicを含むクエリは
UTF-8のファイルとして渡す（Windowsのシェル経由では文字化けする）。

## 処理の流れ（2026-11-05 改訂）

1. 投影（範囲中心の緯度における正距円筒近似）
2. ノード接続数を数え、2以外を「キーノード」（分岐・終端）とする
3. キーノード間のポリラインを「辺」として分解する
4. 各節点で最も直線に近い一対を直進とみなし、残りを分岐側とする
5. 直進で辺を連鎖させ「通し経路」にまとめる
6. **Phase 1**: 通し経路を接続なしで全線敷設する。辺ごとに簡略化して連結し、
   キーノードを頂点として残す
7. **Phase 2**: 共有ノードごとに接続を転記する。途中を通る経路を基準線とし、
   そこで終わる経路を `turnout.attach` で接続する。基準線もそこで終わるなら
   まず `track.connect`（継目）を試す

改訂前は幅優先で敷設しながら接続していたため、構築順序が全域木を強制し、
閉路を閉じる接続が落ちていた。OSM側は共有ノードで接続を持っているので、
これは復元ではなく**転記**であり、幾何と接続を分離すれば素直に書ける。

## 線形破綻の検出と対処（2026-11-05）

初回の実装はブラウザで「何が何やら」判別できない状態だった。
生のOSMと取り込み結果を同じ縮尺で描き比べたところ、原因が判明した。

| | 範囲 |
|---|---|
| 生のOSM way | 7247 × 9671 m |
| 取り込み結果（修正前） | **113103 × 102943 m** |

`sampleArcSegment` は始端接線と弦の向きが食い違うと、ほぼ一周する巨大な円弧を
生成する。直線の接線許容（5度）に収まらず `curve` へ退避した箇所で これが起き、
線路が元の範囲の十数倍へ飛んでいた。曲率が多少荒れる問題ではなく、
形そのものが壊れていた。

対処として、生成後に妥当性を検査し、破綻した線形を撤去するようにした。

- 生成線形長 / 入力ポリライン長 が 1.3 を超えたら破棄
- 最小曲線半径が 40 m 未満なら破棄
- 取り付けに失敗した場合は、形を壊すより**接続を諦めて**未接続で敷設する

結果、91本が破綻として撤去され、範囲は生データと一致した。

## 接続が切れる原因の特定（2026-11-05）

人間確認で「遠くから見れば再現できているが、細部でつながっていない」との
評価を得た。未接続端355件について、最寄りの別線路までの距離を測った。

| 距離 | 件数 | 意味 |
|---|---|---|
| 0.5 m未満 | **167（47%）** | 座標は一致しているのに接続が記録されていない |
| 0.5〜5 m | 120（34%） | ほぼ一致 |
| 5〜60 m | 62（17%） | 転てつ器スタブ長ほどの空き |
| 60 m以上 | 6（2%） | 撤去した線路の穴、範囲端 |

**81%（287件）が5 m以内**であり、線形ではなく接続の記録が欠けている。
`inspectTrackRadii` の接続漏れ候補も166件を検出している。

### 根本原因

取り込みは幅優先で**全域木**を作り、閉路を閉じる辺（225件）を捨てている。
実在の鉄道網は並行線を結ぶ渡り線、両端から入る仕分線群の梯子、三角線など
閉路だらけであり、それらがすべて欠落する。

全域木になったのは、**既存の線路どうしを接続する操作が存在しない**ためである。

| 既存の操作 | 接続点の作られ方 |
|---|---|
| `track.create` | 新しい線路を敷くついでに作る |
| `turnout.create` | 分岐側スタブを生成するついでに作る |
| （なし） | **既存の2線路の間に作る手段がない** |

両端の線路がすでに存在する時点で接続する手段がなく、скипしていた。
データの問題ではなくコマンドAPIの欠落である。

### 接続情報は入力に存在する

OSM側は共有ノードで接続を持っており、測定でも**連結成分1（415 way 全て）**
であることを確認済みである（[取り込み可能性の測定](../research/osm-railway-import-feasibility.md)）。
接続情報は欠けていない。取り込み側が、知っている接続を**記録できない**だけである。

`track.create` は線路を新造する瞬間にしか接続を書き込めないため、構築順序が
全域木を強制する。したがって本質的な対処は「接続の復元」ではなく
「既に判っている接続の転記」であり、次の順序へ変えるべきである。

1. 幾何だけを先に全線敷設する（未接続のまま）
2. 共有ノードごとに接続を転記する

### 必要な操作は物理的に何に当たるか

「任意の2線路を接続する」操作は現実には存在しない。現実に起きるのは次の2つで、
未接続端355件を分類すると内訳も明確に偏っている。

| 現実の行為 | 件数 | 必要な操作 |
|---|---|---|
| 継目（端どうしが合う） | 54 | 端点どうしの接続 |
| **転てつ器の新設**（相手の途中へ入る） | **233** | `turnout.create` が既存線路を分岐側に取れるようにする |
| 5 m以上離れている | 68 | 撤去した線路の穴、範囲端 |

主因は転てつ器の新設である。既設線へ分岐器を挿入して別線を接続するのは
実際の工事として普通に行われる。したがって汎用の接続コマンドではなく、
`turnout.create` に「分岐側スタブを生成する」か「既存線路を分岐側として取る」かを
選べるようにするのが、物理的にも正しく、件数的にも効く。

これは取り込みだけでなく、2026-08-13の接続状態確認タスクが8月から検出し続けている
「接続漏れ候補」に対して初めて手を打てるようにもなる。
