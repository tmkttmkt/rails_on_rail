# Task: Бекасово I の遠隔停車範囲を修正する

## 目的・範囲

OSM版と分割版で、Бекасово I の9停車地点中2地点が駅から遠く離れた2 m区間に移されている。
取り込みが線路全体の最長留置区間を選び、駅位置をそこへ丸めるのが原因である。
駅付近を含む区間だけを採用するよう生成処理を修正し、既存2セーブの当該駅を修復する。
線路・分岐・他駅・留置場分割は変更しない。実物のホーム対応の再調査は対象外。

## 判断・検証

駅の投影位置を含まない区間は採用しない。範囲は駅位置±90 mとの積集合とし、遠い区間へ丸めない。
既存データは7つの180 m区間の中心の中央値を基準に、500 m以上離れた2 m区間だけを削除する。条件に合わない場合や運用参照がある場合は修復を拒否する。
元JSONを拡張子 `.bak` で保存する。保存再読込・差分・回帰テスト・全テスト・ビルドを確認する。

## 結果

- `scripts/repair-bekasovo-i.ts` を両マップに実行。track-21、track-35 の遠隔2 m範囲を削除し9→7停車地点へ修復した。元データは各ファイルの `.before-bekasovo-i.bak` に保持した（OSMデータとしてGit除外）。
- 既存7範囲は変更なし。他駅・全線路・分岐・運用データがバックアップと一致することをJSON比較で確認した。
- 取り込みの `usableSpan` に駅の投影位置を渡し、その位置を含む区間だけを選ぶよう変更。駅近傍との積集合を `selectStationImportRange` で計算する。
- `npm test`: 28ファイル224テスト成功。`npm run build`: 成功。生成後の保存再読込成功。`git diff --check`: 成功。

## 残作業

ブラウザで分割版を再読込し、Бекасово I の表示が駅付近へ戻り、遠隔の強調が除かれることを確認する。原OSMデータがないため再取り込みは未実行。
他の旅客駅にも同種の既存範囲があるが、今回の保存修復は指定されたБекасово Iに限定した。生成処理の再発防止は全駅に適用される。
