# Task: ベカソヴォの巨大な構内停車場を分割する

## 目的

OSM版ベカソヴォでは接続成分による統合で113線路が1停車場になる。暫定的に並行線群単位へ分割したレビュー用セーブを作る。
元セーブを保持し、線路・接続・停車範囲は変更しない。施設の用途の推定、駅グループモデル、旅客駅範囲の修正は対象外。

## 設計判断

分割は既存停車範囲の向き、横間隔、長手方向の重なりを用いる。角度12度以内、横間隔80 m以内、短い方の半分以上重なる組を同じ線群として結合する。
これは実施設の境界ではなく、マップを操作しやすくする暫定ルールである。値はスクリプト側から指定する。
各線群の独立停車場を作る。今回は未運用のベカソヴォマップ専用とし、配置・経路・運行がある入力は出力せず拒否する。
OSMインポーターの全地域共通仕様には適用しない。

## 検証

線路の欠落・重複なし、分割時の参照保護、保存再読込、元データの線路・分岐不変を確認する。ブラウザでの分割境界確認は人間確認とする。

## 結果

- `npx vite-node scripts/split-bekasovo-stations.ts`: 成功。元マップを保持して `saves/osm-bekasovo-split.json` を生成した。
- 113線路を13停車場へ分割（7 / 1 / 2 / 52 / 15 / 1 / 6 / 1 / 2 / 1 / 1 / 20 / 4本）。元の他の停車場4箇所と旅客駅6箇所は変更なし。全23停車場。
- JSON比較で元マップとの線路・分岐・旅客駅・停車範囲の一致、113線路の欠落・重複なしを確認。生成処理内で保存形式の再読込成功。
- `npm test`: 27ファイル221テスト成功。`npm run build`: 成功。`git diff --check`: 成功。
- 生成物はOSM由来の既存除外パターンに従いGit管理しない。

## 残作業・人間確認

サーバー保存一覧で「ベカソヴォ (OSM・停車場分割版)」を開くか、生成JSONを取り込む。線群の境界と名前を確認する。元マップを開いたままでは変更は反映されない。
角度・間隔・重なりによる暫定分割なので、実施設の用途や正確な境界は未確認である。推移的な結合で最大52線路の線群は残る。必要ならレビュー結果から明示的な線路割り当てへ変更する。
旅客駅の範囲が遠隔の同一区間に寄る別不具合も発見した。今回は線群分割と混ぜず未修正として残す。
