# Task: ベカソヴォ操車場を再現したマップを用意する

## 目的

貨車単位の組成・入換を扱うゲーム設計を検討するにあたり、ハンプ式大規模操車場の
配線を現行のマップモデルで表現できるか確認し、将来の入換機能の検証土台を用意する。

モスクワ大環状線のベカソヴォ操車場（Бекасово-Сортировочное）の衛星画像を
参照対象とする。

## 責任範囲

- 受入線群・ハンプ押上線・仕分線群・出発線群・引上線を接続した操車場配線
- 操車場に接する本線と連絡線、および周辺駅
- 生成スクリプトとセーブファイル

## 対象外

- 貨車単位の荷、組成・解結、入換命令、ハンプの仕分能力などのゲーム的意味づけ
  （モデルに存在しない。本Taskは物理配線のみを扱う）
- 実物の線路本数・寸法の測量的な再現
- 運行・運用・編成の作成

## 確定した構成方法

分岐は接線連続でなければ接続できないため、転てつ器は次の方法で表現した。

- **ラダー（分岐梯子）**: 斜めの梯子線を直線の連鎖として敷き、各分岐点から
  二円弧接続曲線（`geometry: "curve"` に始端・終端の両方を接続指定）で
  目標線路の端点へ接続する。
- **両端ラダーの千鳥方向を逆にする**ことで、平行な線群の全線を等長にできる。
- **仕分線群への振り分け**は、v=0の押上線から左右交互に分岐する幹線構造とした。
  外側の束を先に分岐させなければ、内側の束のラダーと交差する。
- 曲線の終端に直線を接続する場合は、曲線へ `endTangent` を明示する必要がある。
- 複線（線路群）の特定の1本へ接続する場合は `connectionAlignmentIndex` /
  `endConnectionAlignmentIndex` を明示する必要がある。既定の中央寄せでは
  群の先頭線路が選ばれ、渡り線が同一線路の両端へ接続されてしまう。

## 実物との差異

- **軌間**: 実物の1520 mmは軌間カタログに未収録のため `gauge-1435mm` で代用した。
  レールはGOST系の `gost-r65`（本線）/ `gost-r50`（構内）を使用した。
- **規模**: 線路本数・線路長・全長は衛星画像の形状から設計した概数であり、
  実物を測量した値ではない。操車場全長は約8.8 kmとなっている。
- **咽喉構造**: 実物の受入・出発咽喉および三角線は複数の短絡線からなるが、
  本マップでは各1〜2本へ簡略化した。
- **周辺駅**: 画面写真から読み取った相対配置であり、実際の駅間距離とは異なる。
