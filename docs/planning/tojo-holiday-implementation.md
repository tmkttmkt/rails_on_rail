# 池袋〜小川町：土休日一日再現の実装順序

## 目的と範囲

上位目標は実用的に遊べるゲームの完成である。東上線は部品を柔軟に差し替えて近似再現する題材とする。営業運転・折返し・入出庫・保守を一日に接続する。本書は東上線MVP内の作業順序であり、旧Phase -1〜6の復活ではない。2026-11-10の追加指示により段階2の実装へ進む。

対象は池袋〜小川町、現在公開されている土休日の定期ダイヤ一日分。途中駅始発・終着と定期TJライナーを含める。地下鉄直通列車は東武線内の区間も除外し、臨時列車・越生線・小川町以北の営業運転を含めない。この除外によって実際とは異なる線路容量・待避条件になるため、「地下鉄直通を除いた再現」と表示する。

営業日は午前0時で打ち切らず、翌暦日の終電・入庫まで連続して扱う。保守作業の確認は、その後の作業と翌朝の最初の回送・営業列車まで含む。

## 実データと仮設定

- 時刻表の取得日・改正日・適用日と出典を固定する。「現在」を後から自動的に別ダイヤへ置き換えない。
- 公開資料で確認した駅・停車駅・時刻と、仮の番線・回送時刻・編成運用・保守計画を分けて記録する。未公開の着時刻や通過時刻を推測で実時刻と呼ばない。
- 編成は運転に必要な長さ・速度・加減速等から定義する。実在形式の正確な性能や実際の充当を未確認のまま断定しない。
- 出典の不足は一覧へ残す。確保できない実運用の代わりに、実行可能なゲーム用運用を構成してよいが仮設定と明示する。
- 全列車の公式照合、実番線、実車性能の完全一致を開発の前提にしない。未許諾データを同梱せず、公開資料で得た運転傾向を参考に独立した仮ダイヤを設定できる。候補604本は参照控えであり、初回の必須列車数ではない。
- 駅順・停車範囲・経路・編成・運転時刻を別の部品として扱う。初回は既存の短編成を使用し、200m級編成や待避設備は必要な試験ごとに拡張する。

## 作業順序と完了条件

|順序|作業|確認できれば次へ進める条件|
|---|---|---|
|1|土休日運転の参考資料を整理する|列車候補、方向・種別・時刻・除外根拠と欠落を引き継げる。完全な現行ダイヤ照合は任意の後続課題とし、未確認値を実時刻と断定しない|
|2|対象線路・駅と試験編成を整える|33駅の上下仮経路と短編成の範囲適合を確認し、初期配置と保存再開ができる。必要な待避設備は段階3の試験に合わせて整備し、未成立の留置・接続は明示する|
|3|少数の列車で時刻運転と進路競合を成立させる|普通と優等列車で停車・通過・待避を試し、同一区間の対向、続行、交差進路を同時に許可せず、安全な位置で待たせられる|
|4|営業列車を一日分へ広げる|全対象列車を実行し、未発車・途中消失・経路不成立・競合・遅延を集計できる。初期配置と終着後の扱いを明示し、途中で編成を都合よく生成しない|
|5|編成運用と入出庫をつなぐ|同一編成で出庫→営業→折返し→入庫を実走し、全営業列車の割当、留置容量、折返し時間、回送の競合、終業時の所在を検証できる|
|6|保守車と作業区間の確保を加える|保守車1編成・作業地点1か所で、競合する最終列車・回送の退出後に出庫し、作業・帰庫・線路開放まで実行できる。営業側と保守側が互いに進入を防げる|
|7|一日全体を通して受け入れる|始発前の配置から最終入庫、設定した夜間作業、翌朝の線路開放まで通して確認し、保存再開と画面上の状態・警告も確認できる|

### 1：調査成果を先に固定する

列車を駅の発時刻だけで数えず、各駅の情報を同一列車へ結びつける。列車番号が取得できない場合は、識別方法と不確実性を記録する。上下の定期列車と途中始終着を漏らさない照合方法を用意する。小川町の境界を越える運行が判明した場合、対象区間内の扱いを明記する。

取得可否と欠落の記録は今回の調査で引き継ぐ。未取得範囲はゲーム用仮ダイヤとして設定できるが、「実ダイヤ一日分確認済み」とはしない。限定トークンの取得は必須でない。

### 2〜3：少数で走行の成立を確認する

既存のLine / ServiceSystem / Route / Operation / VehicleDutyと留置・施設機能を利用し、足りない部分だけを設計する。路線名だけの追加を運行再現の成果としない。旅客範囲が全駅180 m以下だった制約は、2026-11-11に[ホーム端実測の復元](../tasks/2026-11-11_restore-platform-edge-ranges.md)で解消した。合成値ではなくOSMホーム端由来の実測となり、対象33駅のうち31駅が200 m以上を持つ。池袋（180.9 m）と北池袋（199.6 m）はホーム端データ自体が200 m未満であり、長編成を走らせる前に扱いを決める。

進路競合の制御は全日運転より先に確認する。最初から実物の信号機配置・現示・保安装置を完全再現する必要はないが、編成の先頭から最後尾までの占有と進路解放を扱う。時刻どおりに走れない場合は遅延を残し、瞬間移動や速度の無制限な引上げで帳尻を合わせない。

### 4〜5：一日分と編成の連続性を分けて確認する

段階4では必要な編成を初期配置し、営業列車の経路と一日分の時刻処理を検証する。編成運用の完成を待たずにダイヤの欠落を検出できる状態を作る。編成数は一列車一編成を完成仕様とせず、段階5で折返しと共用によって構成し直す。

段階5では、どの列車がどの列車へ折り返すか、駅留置するか、車庫へ回送するかを明示する。終着ごとの即入庫を前提としない。全対象編成について二重割当・場所の飛躍・編成長を超える留置・未処理の入庫を検査する。

車庫・留置線は既存マップを候補とし、実際に進入でき、編成が収まる施設だけを採用する。地下鉄直通を除く条件から東京メトロの和光検車区を東武編成の置き場所に自動転用しない。車庫内の検査・洗浄・複雑な組替えは初回対象外とする。

### 6：夜間保守を運行へ接続する

保守用側線に保守車を初期留置する。営業中の臨時出動は初回対象外とする。実際の保守計画の再現を確認したものとはせず、ゲーム用の作業計画として実装する。

作業には対象の線路区間・出入りする経路・開始可能時刻・必要作業時間・退出と帰庫の所要時間・翌朝までの開放期限を設定する。単に「終電後」という時計条件だけで開始せず、対象区間と接近経路の列車・回送・予約進路の状態を確認する。

保守側の区間確保を営業側の進路予約と共通に検査する。時間不足なら出庫を拒否して理由を表示し、無理に作業を完了させない。作業中に期限へ間に合わなくなる場合も警告し、線路を車両占有中のまま自動開放しない。作業完了・区間外への退出・解除確認によって開放する。留置側線に帰庫した後も、その編成の占有は残る。

初回は線路の劣化、修繕費、資材運搬、複数作業班の最適化を対象外とする。

### 7：再現の完了を判定する

機械確認では対象列車の計画・実行件数、時刻差、進路競合、編成の所在、留置容量、保守の開始条件と開放期限を記録する。安全な待機の結果ダイヤが崩れた場合も、完走だけで合格にしない。欠落資料と時刻精度に応じた許容差は実装Taskで定め、無断で公開ダイヤの再現精度を緩めない。

画面では対象列車・回送・保守車の状態、遅延や待機理由、出典と仮設定の区別を確認する。一日の途中、出入庫中、作業中の保存再開で状態と予約が失われないことを確認する。視認性と操作感は人間確認後に受入済みとする。
