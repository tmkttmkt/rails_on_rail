# 編成の留置配置

`fleet.formation.place` は UI・AI 共通の配置コマンドである。

- 編成全体が指定した停車地点の範囲と線路長に収まることを要求する。
- 3ポート以上、または途中接続を含む接続点を分岐として扱い、編成がその点をまたぐ配置を拒否する。端点間の2ポート継目は除く。
- 分岐に参加する他の線路と編成の占有区間との最短距離を、サンプル線形の線分どうしで検査する。必要中心間隔未満なら留置を拒否する。
- 必要中心間隔は `data/track/stabling.yaml` の暫定ゲーム設定4 mである。車両幅や鉄道規格への適合は保証しない。軌間からの推定ではない。
- 分岐に接続する線路の全体を検査するため、離れた場所で再び近接しても拒否する保守的な仕様である。
- 同一線路の配置済み編成との占有重複も従来どおり拒否する。

保存形式は変更しない。既存配置の再検証、走行中の通過判定、接続関係がない別線路との干渉、施設と留置区間のモデル分離は未実装。

## 留置範囲の生成と表示

`getUsableStablingSpans` は分岐支障区間を除いた複数の区間を返す。境界は最大0.25 m安全側へ切り詰める。
構内の停車場は保存済み範囲とこれらの区間の積集合を描画するため、既存マップにも読み込み後の表示から適用される。旅客駅のホーム表示は変更しない。
保存済み停車地点の値と既存車両配置は書き換えない。
OSM取り込みでは従来の曲線・最小長条件に加えて同じ計算を適用し、最長の利用可能区間を生成する。
現行モデルの同一線路1停車地点の制約により、取り込み時の複数区間保存は未対応。

旅客駅の取り込みでは駅の線路への投影位置を含む区間を選び、その位置±90 mとの積集合を使う。
遠隔の最長区間へ丸めることはしない。該当区間がなければその線路の停車地点を省略する。
旅客範囲には留置用の曲率・横間隔条件を適用せず、実際の分岐接続点で区切る。これはホーム候補範囲の計算であり配置時の留置安全判定を置き換えない。
回帰確認は `tests/stationImportRange.test.ts`、元駅座標からの既存範囲の修復結果は[横断修復Task](../tasks/2026-11-07_repair-imported-station-ranges.md)を参照する。
