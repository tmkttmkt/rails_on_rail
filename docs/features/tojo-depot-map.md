# 東上線・越生線の車庫／留置線マップ

## 開く

`npm run generate:tojo-depots` で生成し、開発サーバーで `/?map=tojo-depots` を開く。既存入力 `saves/osm-tobu-tojo.json` が必要。出力は `saves/osm-tobu-tojo-depots.json`（東武東上線・越生線｜車庫・留置線（OSM））。セーブ管理からの通常読込もできる。

領域版 `saves/osm-tobu-tojo-areas.json` がある場合、専用URLは[構内領域マップ](station-complex-areas.md)を優先し川越市構内を初期表示する。以下は領域版がない場合の基礎マップの挙動である。基礎マップでは森林公園検修区を初期表示する。地図左上「車庫・留置線へ移動」一覧で各施設と全線へ移動できる。赤が選択施設の留置可能区間である。車両は置かず、時計は停止している。地図編集・車両配置は既存機能を使う。

## 収録

池袋〜寄居の東上本線39駅と越生線（坂戸を共用）を合わせ46旅客駅、11車庫・留置施設、266線路。主要施設は下板橋、上板橋、成増、志木、上福岡、川越市、森林公園、小川町。和光検車区は東京メトロの参考施設と明示する。全線を1067 mmへ修正した。その他のレール断面・路盤などは原取込の暫定値を保持し、現地規格の復元を断定しない。

全266線路は一つの接続成分に属する。元取込に含まれた本線から独立するJR等の断片51線路と、対象外の旅客駅を除いた。残した線路の点列は変更せず、存在しない接続は追加しない。

## 留置範囲

旅客ホームと分岐支障を除き、40 m以上の102区間を登録する。200 mに満たない区間を10両用と呼ばない。以下はゲーム内の区間長による判定であり、実際の番線数・収容力ではない。

| 施設 | 留置区間 | 200 m以上 |
|---|---:|---:|
| 下板橋留置線 | 8 | 4 |
| 上板橋引上げ線 | 1 | 1 |
| 成増構内側線 | 4 | 1 |
| 志木留置・引上げ線 | 2 | 2 |
| 上福岡留置線 | 1 | 1 |
| 川越市北側留置線 | 2 | 2 |
| 川越市構内側線（OSM・経路未確認） | 7 | 1 |
| 森林公園検修区 | 40 | 20 |
| 森林公園駅構内側線 | 8 | 0 |
| 小川町留置線 | 3 | 1 |
| 和光検車区（東京メトロ・参考） | 26 | 13 |

各区間について、最寄りの対応旅客駅ホームから有向経路を探索する。直接進入できない場合は、近隣の80 m以上の支障のない側線区間で反転1回を許して探索する。川越市構内側線7区間は正しい旅客ホームからの経路を確認できず、施設名に「経路未確認」と明示して形状のみ保持する。到達確認済みは95区間である。小川町の未確認1区間は留置登録から除き、線路の描画は保持した。

この検証は接続方向の検証であり、200 m編成を使った入出庫全行程の実走ではない。引上げ余裕・ダイヤ・信号・本線との競合は別途必要である。

## 出典と限界

基準はローカルのOSM取込データ（2026-11-06作成・11-07駅範囲修復）である。今回のOverpass再取得は502／タイムアウトとなり、最新データへの更新は行っていない。旧工場を含む川越市の側線が現地で現在使用できるという意味ではない。

出典: © OpenStreetMap contributors / ODbL。派生地図と診断はGit対象外。設定・生成コードのみを管理する。入力SHA-256、区間ごとの除外理由と長さ、到達検証は `saves/osm-tojo-depots.report` に記録する。

## 旅客駅の監査で判明した問題

[全46駅の監査](../research/tojo-station-shape-audit.md)で、公式図と旅客線路数が不一致の駅が10駅、5 m等の極短範囲、全駅180 m以下という取込上の問題が判明した。留置線の接続確認は旅客ホームの妥当性を保証しない。[所属補正](../research/tojo-station-track-corrections.md)で10駅の余分な19範囲を除き、旅客線路数の不一致と80 m未満の範囲は0になった。固定180 m以下の制約とホーム形状の描画は修正待ちである。

一般の[OSM取込器](osm-passenger-import.md)もホーム照合方式へ修正済みである。車庫マップは既存スナップショット用の個別補正を引き続き使い、新取込の未確定駅で置き換えない。小川町の個別所属は後続検証で訂正した。

## 小側線の操作試験

[側線施設機能](siding-facilities.md)により施設を選んで用途を設定し、試験車を配置して本線との往復を確認できる。上福岡の開始前セーブは `npm run verify:siding-trial` で作り、`/?map=siding-trial` から開く。元の車庫マップを上書きしない。

## 構内全体の整理

[構内・車両基地グループと用途領域](station-complex-areas.md)が領域整理の現在の入口である。`npm run generate:tojo-areas` で9グループ65領域を別生成し、`/?map=tojo-areas` または従来の東上線URLで開く。基礎データは生成入力として保持し、線路・旅客駅は変えない。
