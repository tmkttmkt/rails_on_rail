# 構内・車両基地グループと用途領域

広義の停車場を「構内・車両基地グループ → 用途領域 → 停車可能区間」の三段階で扱う。平行線路の編集用TrackGroupとは別の所属であり、同じ線路を距離で区切って異なる領域へ割り当てられる。

## 開く・生成する

`npm run generate:tojo-areas`。既存 `saves/osm-tobu-tojo-depots.json` が必要。設定は `data/maps/tojo-station-areas.yaml`。出力は `saves/osm-tobu-tojo-areas.json` と `saves/osm-tojo-station-areas.report`。元入力と車両試験セーブは変更しない。

開発サーバーの `/?map=tojo-areas` で全グループが入る位置を表示し、どのグループも選択しない。`?focus=`に領域名・領域ID・グループIDを渡した場合だけ、その対象を選択して移動する。領域版がある場合は既存 `/?map=tojo-depots` も領域版を優先する。用途領域の色面・番号と編集欄は「施設」タブだけで表示し、「地図」へ切り替えると隠す。グループ自体は全モードの地図に表示する。最上部の「施設」タブを開いた直後はどのグループも選択せず、左パネルにグループ一覧を出す。一覧または地図上のグループをクリックして編集へ入り、「グループ一覧へ戻る」で一覧へ戻る。地図上の専用ボタンや重ね置きパネルは使わない。

現在は12グループ・35領域、全46旅客駅を保持する。旅客ホームはグループへ入れず、独立した駅として保持する。通常運行の設備（待機線・引上げ線・構内側線）と車庫・検修・保守の設備を同じグループへ混ぜない。川越市の指定構内区間（旅客ホームと旧2番の線路を除く）を3グループ合計で、他9グループの元施設対象側線と本線接続部の指定範囲を各グループで、未所属の残余区間がないことを生成時に検査する。本線接続部の範囲に旅客ホームが掛かる場合も、分岐接続通路がホーム範囲を所有しないことを確認する。指定範囲外の全本線・全OSMを自動分類したという意味ではない。数値上0.01 m以下の端部は丸め誤差として扱う。

## 川越市の区分

旅客ホームと旧2番の北側線路はグループ外。運行用の待機・引上げ、保守用側線、旧工場側の留置・作業線を3グループへ分ける。残余の分岐区間は北側を保守側、南側を旧工場側へ所属させる。北側の分岐・接続区間は残余区間の仮分類であり、単一の入換経路として検証していない。

|川越市北側保守用側線|北側の分岐・接続区間（仮）|分岐・咽喉部|0|0.0 m|

南側引上げ領域は約196 mを所有するが、分岐支障を除いた停止可能区間は約106 mである。領域の長さをそのまま留置可能長と呼ばない。引上げ線は一時的な入換停止用であり、通常の留置配置は拒否する。分岐・接続通路には停車場を生成しない。

旧工場側などの用途はゲーム上の仮区分で、実際の現役用途・正式番線・検修設備の復元を断定しない。旧工場への有向進入経路は従来から未確認であり、本件は領域の整理と安全な停止区間の分離である。

各グループの領域数には分岐接続通路1領域を含む。成増と小川町の各1線領域は、幾何的に独立した単独側線であり本数の上限による分割ではない。

森林公園は検修区と駅構内側線を別グループへ分ける。グループ名は駅名ではなく設備を指す。各グループは自分の分岐接続通路を持つ。「志木留置・引上げ線」は留置と引上げを1領域に含む元施設区分のままであり、未分離である。

留置区間は平行方向・長手方向の重なりで分ける。領域は幾何的な線群とそのまま一致させ、線路の本数で機械的に割らない。

**同じ線路の停車範囲は必ず同じ領域へ入れる。**分岐支障で分断された同一線路の区間は長手方向に重ならないため、区間単位の判定だけでは同じ線路が複数の領域へ分かれ、1区間だけの領域が余る。

線群を本数の上限でさらに割らない。同じ扇状の線群がx座標順の任意の位置で二つに分かれ、区別のない領域が増える。線数の多い領域（森林公園検修区の14線、和光検車区の16線）は、実際に並行して長手方向が重なる一つの線群である。森林公園や和光の建物機能ごとの実区分を確定したものではなく、後から再編できる線群単位の区分である。残る分岐・接続部分も通路領域として保持する。

## 操作

領域一覧を押すと、その領域へ移動・強調表示する。番号と色が地図と一覧で対応する。番号は所属グループ内の順であり、複数グループが同時に見えても一覧と一致する。グループ全体の外周は破線、領域は色面、通路は線状に表示する。表示面は線路区間から生成する包絡であり、土地境界や測量図ではない。

縮小するとグループを名前と領域数を添えた一つの部品として描き、所属停車場のマーカーを置き換える。拡大すると所属する駅部品へ展開する。切替はグループの外接矩形の長辺×表示倍率が画面上140 pxに達するかで判定し、グループごとに独立して切り替わる。グループに属さない停車場は倍率によらず常に駅部品として表示する。折りたたみ中のグループは地図のクリックで選択でき、選択だけでは視点を動かさない。視点移動は一覧または「構内全体を見る」で行う。

グループを選ぶと、用途領域数・線路数・停車区間数・役割の内訳・最長の停止可能長・構内の広がりを右パネルに表示する。駅・停車場を選ぶと、停車地点ごとの線路・長さ・方向の一覧、最長と最短、編成長が入る線数、所属グループと領域、ホーム未確定理由を表示する。編成長の可否は20 m車を前提にした長さ比較の目安であり、車両データから計算した値ではない。

施設タブで停車場の種別を変更できる。領域が種別と用途を決めている停車場では拒否し、領域編集へ誘導する。領域の削除は区分だけを解除し、線路と停車場を残す。解除後はその停車場の種別を停車場側から変更できる。領域のない空のグループは削除できる。

選択領域では名称・用途・所属グループを変更できる。「この領域をさらに分割」で線路群を選び分けるか、単一区間なら始端からの距離で前後を分ける。元区間を過不足なく分けることと、分割先同士が重複しないことを検査する。停車可能区間は再計算し、短い分割先に無理に作らない。旅客ホーム領域の分割・用途変更はこの画面では対象外。

新規グループは選択施設・側線から作れる。グループがない通常マップでも、「施設」タブで空のグループ作成欄を表示する。既存停車場を領域として追加するか、選択側線の未所属部分を用途未確認の領域として追加し、その後用途を指定する。既存領域へ重なる部分は登録しない。

区分中の線路・分岐、関連停車場を従来の個別編集から壊す操作は拒否する。領域から再編するか区分を解除してから編集する。車両が配置・運転中の領域構造変更は拒否する。名称変更は可能。

## 保存と検証

MapState v15へグループ・領域・カウンタを保存する。v14以前は既存停車場を保ち、空の階層を追加して移行する。親・関連停車場の欠落、範囲重複、関連停車範囲の逸脱、非旅客停車範囲の分岐支障を検証する。

`npm run generate:tojo-areas` 成功。全9グループの指定範囲の未所属0、領域間重複0、線路266本・接続点・転てつ器と全46旅客駅の不変を比較確認。全271テストとビルド成功。ビルドには500 kB超の既存一括バンドル警告があるが失敗ではない。

ブラウザーで川越市の全体・個別領域、引上げ線の90 m位置での二分割（9→10領域）、親所属保持と前側の停車区間0、森林公園20領域への切替を確認した。実際の信号連動・ダイヤ運転・全入出庫の実走は今回の対象外である。

## 建設との責任分担

駅・操車場などの部品の新設、拡張、撤去など物理変更は「建設」。駅グループの作成・名称・所属と既存領域の分割・用途指定など管理上の編集は「施設」。グループ名も左パネルから変更できる。既存の駅名変更は施設の右パネルで行う。操車タブの整理は別作業とする。
