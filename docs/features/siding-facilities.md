# 側線施設の用途指定と保守車の往復試験

## すぐ試す

`npm run verify:siding-trial` は既存 `saves/osm-tobu-tojo-depots.json` を読み、上福岡留置線をゲーム内で保守用に指定した操作試験を作る。出力は `saves/osm-tojo-siding-trial.json` と検証報告 `saves/osm-tojo-siding-trial.report`。既存入力は変更しない。

開発サーバーの `/?map=siding-trial` を開くと、試験用保守車1両を配置した上福岡留置線が表示される。「建設」タブの右パネルの「本線へ出て側線へ戻る」で動き始める。1×ではゲーム内約182秒。上の60×で早送りできる。移動中はカメラが車両を追い、完了すると「本線往復完了・側線に留置」と表示する。「試験車を撤収」で取り除ける。途中で停止したい場合は上の時間ボタンを使う。

この用途指定は操作試験の設定であり、現地の上福岡側線が保守用であるとの断定ではない。試験車は12 m・1067 mmの仮想自走車である。

## 自分で設定する

既存マップでも利用できる。建設モードで側線を1本選ぶと右パネルに施設登録欄が出る。名前を付けて登録すると、ホーム・既存施設・分岐支障を除いた範囲が作られる。既にある施設はその施設を選ぶ。

用途変更は「施設」タブで行い、試験車の配置・往復操作は従来の試験機能として「建設」の右パネルに残す。

施設用途は「用途未確認・留置線・引上げ線・保守用側線・車庫／検修施設」。用途設定と施設区間は保存される。引上げ線と用途未確認は留置用に配置できない。留置・保守・車庫のいずれかに指定し、「試験用保守車を配置」を押す。車長・分岐支障・本線往復経路・軌間が合わなければ理由を表示して拒否する。

用途だけを変えて検査・洗浄等が実装されるわけではない。試験中の施設変更や線路編集は拒否するため、先に車両を戻して撤収する。

## 検証結果

上福岡の元OSM配線のまま、track-155の約223.8 mの留置範囲からtrack-1へ出て反転し、元位置と向きへ戻る4工程を完走した。ゲーム内182秒。本線の占有を検出し、途中保存を読み直して継続した。完了後のfleet個体・車両順、元線路・接続点・転てつ器の不変を比較確認した。

ブラウザーでも用途設定・配置・出庫・入庫を操作し完了表示まで確認した。全265テストとビルド成功。合成配線では誤軌間・不足長・未確認用途・引上げ線・旅客駅・重複配置・運転中の撤収・壊れた保存参照を拒否することを検証している。

現段階は空いている本線上での単車の入出庫確認である。信号連動、ダイヤとの競合、実車性能、電化条件、保守作業は未実装。車庫全体の運用が完成したという意味ではない。
