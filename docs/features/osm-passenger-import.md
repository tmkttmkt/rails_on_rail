# OSM旅客ホームの取り込み

`scripts/import-osm-map.ts` の旅客駅生成は、駅付近の線路を距離だけで登録しない。元の線路・駅JSONに加え、ホームのway形状と事業者情報を使う。駅の存在は停車範囲の確定と分離して保持する。個別駅名・線路IDの例外は持たない。

## 判定

- `railway=platform` または `public_transport=platform` のwayのみをホーム候補とする。Overpassのgeometry形式と、nodes参照＋node要素形式を読む。面ホームと線ホームに対応する。relationのみ・点だけのホームは未対応。
- 駅から250 m以内のホーム、150 m以内を通る線路を候補とし、ホーム縁を5 m以下の間隔で照合する。距離8 m以内、接線の内積絶対値0.94以上の平行線路を比較する。
- 面ホームでは各縁の最寄り線路、線ホームでは両側それぞれの最寄り線路を選ぶ。面の内部を通る線路は採用しない。候補間の距離差0.5 m未満は曖昧として除外する。
- 元wayの局所的なoperatorを駅のoperatorと照合する。駅operatorが局所線路に存在しなければ、network、既知駅のref接頭辞が一意に対応する事業者、operator欠損時に局所ホームと一致する唯一の事業者を順に利用し、根拠を診断へ残す。複数事業者が対応する場合は未確定にする。セミコロン区切りの共通値のみを一致とし、別名の推定はしない。service=yard/spurは除外する。sidingは旅客ホームにも使われるため一律除外しない。他社線・構内線が最寄りなら、それを飛び越して奥の自社線を選ぶこともしない。
- 連続した対応からホーム端を線路距離へ投影する。点で触れるだけ、20 m未満、ホーム全体の広がりの60%未満の断片は採用しない。分岐で切った後に20 m未満または元対応長の80%未満になれば未確定とする。これらは誤生成を抑える取込上の閾値であり、現実のホーム長の規格ではない。
- 最寄り線路の無条件採用、ホーム欠損時の近傍全線への代用、固定180 m生成は廃止した。ホーム未提供・事業者欠損・曖昧な対応を推測で埋めない。短い実ホームや複雑な共用駅は未確定になり得る。

## 実行と診断

`npx vite-node scripts/import-osm-map.ts <線路JSON> <出力セーブ> <名前> <駅JSON> <ホームJSON> [鉄道用地JSON]`

旅客駅診断は `<出力セーブ>.stations.report`。駅名・事業者・状態・警告・元ホームway ID・線路ID・投影範囲を記録する。`unresolved` は停車範囲未確定であり、駅は名前・位置・理由付きでゲーム内に保持する。`imported-with-warnings` は一部の対応を含めて確認が必要な駅である。`imported` も実物の番線数が完全であることの保証ではない。外部のホーム情報不足は推測で補完しない。線路・構内施設の取り込みは旅客駅が未確定でも続ける。

検証: [Task](../tasks/2026-11-08_fix-osm-passenger-platform-matching.md) / [調査・回帰結果](../research/osm-passenger-platform-matching.md)。

## 判明した欠落の原因

[9駅の個別調査](../research/osm-missing-stations-causes.md)により、6駅はホームが存在するのに駅operator欠損だけで除外されていた。現在は[未確定駅の保持](../designs/unresolved-import-stations.md)を実装し、欠落を解消した。

## 修正後の東上線実データ検証

46対象駅の欠落0。従来欠落した池袋・東武竹沢・みなみ寄居・男衾・鉢形・玉淀は停車範囲を生成した。寄居・西大家・武州長瀬は位置と名前を残し「ホーム未確定」と表示する。中板橋・和光市の一部ホーム不足は継続する。

再取込マップは `/?map=tojo-import&focus=みなみ寄居`。左上「駅・施設へ移動」で未確定駅にも移動でき、選択パネルに理由を表示する。元入力から `saves/osm-tojo-import-regression.json` を生成する必要がある。旧車庫マップは `/?map=tojo-depots` のまま別に保持する。

保存形式v14は未確定理由付きの空の旅客駅を許可する。v13以前を移行して読める。未確定駅には車両を置けない。確定したホームを別に作成し、駅統合で取り込むと未確定状態を解消できる。
