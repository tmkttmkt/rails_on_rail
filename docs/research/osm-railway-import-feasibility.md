# Research: OpenStreetMapの鉄道データ取り込み可能性

## 目的

手作業で設計した操車場マップが実物と異なるとの評価を受け、OpenStreetMap（OSM）の
鉄道データを現行のマップモデルへ取り込めるかを、実データの測定によって判断する。

## 前提の整理

`openrailwaymap.app` は独自のデータを持たず、OSMデータを鉄道向けスタイルで
描画するビューアである。線形データの取得先はOSMであり、範囲取得にはOverpass APIを使う。

## 測定方法

- 対象: ベカソヴォ操車場周辺（Бекасово-Сортировочное: 55.41861, 36.8717）
- 範囲: 緯度 55.37〜55.45、経度 36.82〜36.93
- 取得: Overpass API へ `way["railway"~"^(rail|narrow_gauge)$"]` を問い合わせ（351 KB）
- 投影: 緯度55.41における正距円筒近似（1度 = 緯度111320 m / 経度63166 m）

## 測定結果

### 規模と網羅性

| 項目 | 値 |
|---|---|
| way数 | 415 |
| node数 | 2419 |
| 総延長 | 240.6 km |
| `service=yard` | 264 way / 153.2 km（最長2133 m、中央値383 m） |
| 本線・service無し | 96 way / 63.6 km |
| `crossover` / `siding` / `spur` | 22 / 20 / 13 way |

構内配線は詳細に整備されている。仕分線群は264本規模で収録されており、
手作業で設計した32本を大きく上回る。

### トポロジー

| 項目 | 値 |
|---|---|
| 連結成分数 | **1**（415 way すべて） |
| 分岐ノード（2 way以上が共有） | 516 |
| 転てつ器ノード（3分岐以上） | 469 |

ノード共有による接続が完全に取れており、断絶はない。

### 接線連続性

ゲーム側の許容角は `TANGENT_ANGLE_TOLERANCE_RAD = 5度`（`src/simulation/geometry.ts:5`）。

**直進側**（各分岐ノードで最も直線に近い組の、直線からのずれ）

| 統計 | 値 |
|---|---|
| 中央値 | 0.48度 |
| 90パーセンタイル | 3.73度 |
| 5度以内 | **483 / 516（93.6%）** |

**分岐側**（転てつ器ノードで直進側を除いた最小の発散角）

| 統計 | 値 |
|---|---|
| 中央値 | **7.0度** |
| 5度以内 | 127 / 469（27.1%） |
| 10度以内 | 394 / 469（84.0%） |

### ノード間隔

| 区分 | 中央値 | 25% | 75% |
|---|---|---|---|
| 構内線（yard） | 41.0 m | 27.3 m | 63.7 m |
| 本線・その他 | 48.1 m | 29.4 m | 89.2 m |

## 判明したこと

1. **トポロジーと網羅性は問題にならない**（少なくともこの地点では）。
   事前に懸念した「ノード共有の断絶」「構内配線の欠落」はいずれも観測されなかった。
2. **直進側の接線はほぼそのまま通る**（93.6%が5度以内）。線路の連鎖は素直に構築できる。
3. **実際の障害は転てつ器の分岐側である**。OSMでは分岐線が中央値7.0度で
   ノードから離れていくため、現行の接線検査では73%が拒否される。
   これはデジタイズの粗さによる見かけの角度であり、実物の転てつ器は
   分岐点で接線連続である。約40 m先の最初のノードまでに横へ4〜5 m動いた
   結果が7度として現れている。
4. **円弧構造は存在しない**。OSMは点列のみを持ち、半径・緩和曲線・カントを持たない。
   ただしノード間隔40 m級は、本線の曲線半径（500〜2000 m級）へ円弧を
   当てはめるには足りる粒度である。

## 結論

取り込みは実現可能であり、障害は事前の想定より小さい。
必要な処理は次の通りで、4が本体となる。

1. 投影（緯度経度 → 局所メートル座標）
2. 分岐ノードでのway分割と `TrackJunction` への変換（データが清浄なため機械的）
3. タグからの属性取得（`gauge`、`maxspeed`、`electrified`）と残りの既定値補完
4. **転てつ器の再構成**: 分岐ノードで分岐線を接線連続な開始へ作り直し、
   二円弧で目標線路へ接続する。`2026-11-03_create-bekasovo-yard-map` で
   確立した構成方法がそのまま適用できる
5. 粗いポリラインから円弧チェーンへの当てはめ

## 未解決事項

- **ライセンス**: OSMはODbL。生成セーブをリポジトリへ含めて配布する場合、
  継承と帰属の義務が生じる。`data/sources.yaml` への登録方法と併せて判断が必要。
- 本測定は1地点のみ。ベカソヴォは整備度の高い地点であり、他地域で同等とは限らない。
  ただし同じ測定を他地点へ適用して判定できる。
- レール断面、支持方式、路盤はOSMに存在しないため既定値補完となる。
