# OSM旅客ホーム照合の修正と回帰結果（2026-11-08）

## 根拠と判断

OSMの[railway=platform](https://wiki.openstreetmap.org/wiki/Tag:railway%3Dplatform)はホームを表し、[operator](https://wiki.openstreetmap.org/wiki/Key:operator)は運営主体を表す。これらの元way属性と幾何を使う。ただし、ホームが近いという一点の条件から旅客線路と断定はできない。[従来の全駅監査](tojo-station-shape-audit.md)で、側線・他社線の混入と極短範囲、固定180 mを確認した。

距離・平行性・最寄り縁・連続長・局所的事業者を併用する方式は本プロジェクトの保守的な推定であり、OSMの標準仕様が配線の完全自動判定を保証するものではない。詳細は[現在仕様](../features/osm-passenger-import.md)。

## 元データの再取込

前の駅修復Taskに記載の一時保存先から `tojo4.json` / `stations.json` / `platforms.json` を使用した。出力は別ファイル `saves/osm-tojo-import-regression.json`、診断は同名末尾 `.stations.report`、実行ログは `saves/osm-tojo-import-regression.report`。既存入力と手修正マップを新取込で置換していない。最新OSM再取得ではない。

全46対象駅のうち37駅を取り込み、35駅は公式参照の物理的旅客線路数に一致した。本数一致は全番線・全ホーム端の現地一致を保証しない。

- 中板橋は3/4線、和光市は2/4線のみを登録し、警告を伴う。和光市では共有するホームと事業者の関係を、事業者タグの単純一致だけで完全に復元できない。
- 未登録9駅: 池袋、東武竹沢、みなみ寄居、男衾、鉢形、玉淀、寄居、西大家、武州長瀬。事業者欠損・別名、ホーム情報不足や対応不足を診断へ残した。池袋の元駅operatorは `Tojoouter` であり、東武鉄道への別名変換を推測しない。寄居は駅operator欠損のため他社線も含めて推測登録しない。
- 従来不一致の朝霞・志木・新河岸・川越市・坂戸・高坂・森林公園・小川町・越生は、駅別例外を使用せず正しい本数に一致した。寄居は未確定となり、従来の9線登録を再現しない。
- 新規の停車範囲はホーム端由来であり、180 m固定ではない。既存手修正マップの範囲を自動延長する変更は行っていない。

## 小川町の前回手修正の訂正

前回は track-168 を残し track-164 を除く判断が誤っていた。自動照合では元ホームway/843115842の両縁が track-164 / track-165 に対応する。残す4線を track-1 / track-164 / track-165 / track-171 へ訂正した。track-168 は同じ側のより外側の側線である。前回の本数だけの検証では検出できなかったため、ホーム縁への対応を追加の根拠とした。

設定を訂正して既存車庫マップを再生成し、全46駅の本数不一致0、極短範囲0を再確認した。前回の調査報告はその時点の判断の記録として残し、訂正リンクを付けた。

## 回帰テスト

`tests/osmStationPlatforms.test.ts` の9ケース、`tests/stationImportRange.test.ts` のホーム範囲3ケース、`tests/osmImportCli.test.js` のCLI統合1ケースを追加した。疎なホーム頂点、島式・線ホーム、余分な側線、点接触・横断、他駅ホーム、局所事業者、他社線を飛び越す誤選択、欠損・曖昧さ、極短断片・分岐欠落・220 mの保持を確認する。

CLIテストは合成したOSMを一時ディレクトリで実際に取り込み、2本のみ・220 mの出力、ホーム未提供時の旅客駅0と未確定診断を検査する。通常の `npm test` に含むためViteのtest includeをts/jsへ拡張した。Node型依存の追加は行っていない。直線のみの入力で曲率統計が空でもログ出力できるよう修正した。

`npm test`: 31ファイル251テスト成功。`npm run build`: 成功。元OSM再取り込み・保存再読み込み成功。今後は未確定駅についてstop_area等の関連情報や明示的な出典付き補足が必要であり、全駅の完全自動復元を達成したとは扱わない。
