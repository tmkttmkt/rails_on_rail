# OSM取込で欠落した9駅の個別調査（2026-11-08）

## 結論

9駅を一律に「ホームや資料不足」と説明したのは不正確だった。6駅はホーム形状・線路とも入力に存在するが、駅operator欠損だけで照合前に除外された。残りは池袋の事業者文字列不一致、西大家の入力ホーム形状欠損、武州長瀬の面ホーム処理の前提不一致である。実物の駅が存在しないことを示す結果ではない。

## 再現方法と資料

前Taskのローカル `tojo4.json` / `stations.json` / `platforms.json` を使い、取込器のPhase 1/2と実際の `passengerTracks` / `platformPolylines` 構築直後に調査処理を挿入した一時コピーを実行した。本番コードは変更せず、一時コピーは終了後に削除した。

判定関数の実行条件を以下の三通りで比較した。

- baseline: 元の駅operatorをそのまま使用。
- stationOperatorOnly: 診断上のみ駅operatorを「東武鉄道」に変更し、線路・ホーム属性と幾何は維持。
- geometryOnly: 診断上のみ事業者・構内用途の制約を外し、幾何による追加阻害を確認。

この条件変更は原因を切り分ける反実仮想であり、欠損した事業者を一律に東武と補完してよいという結論ではない。寄居でgeometryOnlyを実行するとJR・秩父を含む6旅客線路が一致するため、事業者や路線の所属を別の根拠で区別する必要がある。

出力は `saves/osm-station-omissions.report`、武州長瀬の対応区間は `saves/osm-station-contact-probe.report`、幾何検査は `saves/osm-missing-station-geometry.report`。OSM由来のためGit対象外。© OpenStreetMap contributors / ODbL。

## 池袋

東武側の駅node/7093641218のoperatorは `Tojoouter`、線路の局所operatorは「東武鉄道」であり文字列が不一致。baselineは一致0。駅operatorだけを東武に設定した反実仮想では track-281 / track-1 / track-8 の3線が得られた。ホームがないための欠落ではない。

operatorは人間可読の名称で表記の揺れがあり、OSM Wikiは識別を確実にする方法としてoperator:wikidataにも言及している。[OSM operatorの説明](https://wiki.openstreetmap.org/wiki/Key:operator)。ただし、この入力の `Tojoouter` の意味を名称の類似だけで自動補正したわけではない。駅refや所属関係等を併せた解決が必要である。

## 西大家

駅node/2964285318とtrack-5は存在し、駅から線路まで約6.6 m。駅operatorも東武で正しい。しかし入力706ホームwayの最寄りは約1072 m先で、250 m候補に1本も入らない。取得クエリは `(35.70,139.15,36.15,139.76)` の範囲で、西大家の位置は範囲内。単なる検索半径拡大や事業者補完では直らない。

追加で公開OSM APIから駅付近の小範囲 `(139.3538,35.9300,139.3588,35.9333)` を取得した。駅nodeと `building=train_station` / `public_transport=station` のway/485300434はあるが、鉄道ホームを表すnode/way/relationは見つからなかった。バス停のpublic_transport=platformはあるため、これを鉄道ホームに流用してはならない。取得応答は `saves/osm-nishi-oya.osm`。これは調査時の当該範囲の応答であり、OSM全体に関連情報が一切ないと断定はしない。

[公開OSM APIの調査範囲](https://api.openstreetmap.org/api/0.6/map?bbox=139.3538,35.9300,139.3588,35.9333)。駅の存在と、実ホーム端を復元できることは分ける必要がある。

## 武州長瀬

駅node/7965143821、operator=東武鉄道、ホームway/484471939はいずれも入力に存在する。ホームは19頂点の閉じたarea=yes / railway=platform / public_transport=platform。駅から境界まで約8.1 m。

この面は線路track-3 / track-5を囲む形であり、本実装の「面ホームの内部に線路中心が入れば除外」という前提に合わない。実際の辺サンプルでは8 m超の距離条件と面内部除外で大部分を落とし、残るtrack-5の対応は0 mと約5.38 mの断片のみだった。期待するホームの広がり約112.27 mに対し20 m・60%の条件を満たさず全範囲が拒否された。事業者条件を外しても結果は変わらず、タグ欠損ではなく幾何の扱いが直接原因である。

元ホーム表現を、独立した一つのホーム本体の外周であると一律に解釈した実装側の制約がある。現地の測量との照合は行っておらず、OSM形状自体の正誤までは断定しない。

## なぜ地図から駅ごと消えるか

1. `src/simulation/osmStationPlatforms.ts:46` が駅operatorなしなら即returnする。
2. 他の不一致でも対応範囲は0件となる。
3. `scripts/import-osm-map.ts:542` は作成できた範囲が0件なら、駅を作らずcontinueする。
4. `src/simulation/persistence.ts:177` はstopPointsが空の駅を不正なセーブとして拒否する。

したがって「未確定として残す」は診断JSON上だけであり、ゲーム内の駅として残す実装ではなかった。ログと取込結果の概念を混同した説明も訂正する。

## 必要な修正

駅の存在・名称・位置と、旅客停車範囲の確定を分ける。駅の未確定状態を保存・描画・操作系まで一貫して扱い、未確定駅に列車を配置できないようにする。所属解決ではrelationや識別子・路線情報等を併用し、単一operatorの欠損を駅の削除理由にしない。ホーム形状が不足する西大家と、表現が前提に合わない武州長瀬は、範囲確定と駅の保持を分けて扱う必要がある。

今回は調査のみ。地図・取込器・セーブ形式の修正とコミットは行っていない。取込失敗は元スナップショットと現コードで再現し、反実仮想の切り分けを実行した。前Taskの251テスト成功はこの9駅の保持を検証したことにはならない。
