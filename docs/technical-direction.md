# 技術方針

## 基本方針

当面はWeb技術を使用する。

初期段階では開発速度と変更容易性を重視し、将来的な性能問題が実際に発生するまでは過度な最適化を行わない。

## 想定技術

- TypeScript
- Vite
- 2D描画ライブラリ
- 地図表示ライブラリ
- 必要に応じてReact

地図表示については、現実の地理情報を扱いやすい構成を検討する。

## 構造

ゲームのシミュレーションと表示処理を分離する。

```text
シミュレーション
        ↓
    ゲーム状態
     ↙      ↘
   地図      UI
```

シミュレーション部分は可能な限り特定の描画ライブラリやUIフレームワークに依存させない。

## ディレクトリ方針

初期案。

```text
src/
  simulation/
  railway/
  map/
  economy/
  ui/

data/
  eras/
  rails/
  vehicles/
  infrastructure/
  technologies/

assets/
  icons/
  sprites/
  ui/
```

Rails on Rail では画像資産よりもゲームデータが重要になるため、`assets` より `data` が大きくなる構成を想定する。

## データ駆動

以下の情報は可能な限りコードへ直接埋め込まない。

- レール規格
- 車両
- 技術
- 年代
- インフラ設備
- 信号方式
- 電化方式

JSONなどの外部データとして定義し、追加や変更を容易にする。

## 性能

初期段階ではTypeScriptのみで実装する。

性能上の問題が発生した場合は、以下の順で対応を検討する。

1. アルゴリズムの改善
2. データ構造の改善
3. Web Workerによる並列化
4. 描画処理の最適化
5. 必要な処理のみRustとWASMへ移行

最初からRustやネイティブゲームエンジンへ依存することは避ける。

## 2D表示

Rails on Rail は2Dを基本とする。

車両や施設の詳細な3D表示よりも、以下の情報を地図上で確認できることを重視する。

- 路線
- 駅
- 列車
- 最高速度
- 軸重制限
- 設備状態
- 収益
- 輸送量
- 保線状態
- 廃線予定
- 工事区間

表示モードを切り替えることで、同一の地図から異なる鉄道状態を把握できる設計を目指す。
