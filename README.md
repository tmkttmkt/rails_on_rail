# Rails on Rail

鉄道の規格・車両・歴史・経営を詳細に扱う2D鉄道シミュレーションゲーム。

## 名称について

「Rails on Rail」という名称には、**複数の複雑な鉄道規格（Rails）が、歴史という一本の線路（Rail）に乗っている**という意味を込めている。

## 概要

Rails on Rail は、長期的な鉄道経営と鉄道技術の発展を扱う2Dシミュレーションゲームである。

単に線路を敷き、列車を走らせることだけを目的としない。線路や保安設備の規格、車両、輸送、維持、更新、経営、衰退、廃線までを、一つの連続した鉄道史として扱う。

地図上で鉄道網を扱う操作性と、数値・表・詳細な内部状態を重視し、長期間の運営の中で過去の判断が将来の制約となるゲームを目指す。

## 中心コンセプト

### 規格を管理する

鉄道は単一の「線路レベル」で表現しない。

軌間、レール、軸重、建築限界、電化方式、信号、閉塞、保安装置、橋梁、線形、駅設備など、鉄道を構成するさまざまな規格を扱う。

新しい規格や高性能な設備には利点がある一方、建設費、維持費、既存設備との互換性、更新範囲などの問題が生じる。

単純な上位互換ではなく、どの選択にもトレードオフが存在することを重視する。

### 車両を管理する

蒸気機関車、電気機関車、ディーゼル機関車、電車、気動車、客車、貨車など、時代に応じたさまざまな車両を扱う。

車両には出力、速度、重量、軸重、牽引力、燃費、信頼性、保守性などの特性を持たせ、路線側の規格との適合を必要とする。

高性能化、価格、維持費、汎用性、専門化、路線適合性などの間にトレードオフを持たせる。

### 鉄道史を進める

鉄道は歴史の背景ではなく、時代を前に進める存在として扱う。

新線の建設や輸送力の向上によって都市、産業、人口配置、時間距離が変化する。その一方で、自動車、航空、人口変化、産業構造の変化などによって、鉄道自身も再編を迫られる。

建設だけではなく、改良、更新、維持、減便、転換、休止、廃線までを判断対象とする。

過去に選択した規格や設備投資が数十年後まで影響を残し、鉄道が時代を変え、その時代の変化によって鉄道自身も変化を迫られる循環を目指す。

### トレードオフを中心に置く

Rails on Rail では、唯一の正解となる設計や経営方針をできるだけ作らない。

- 高性能と維持費
- 高規格と建設費
- 標準化と路線ごとの適応
- 新技術と既存設備との互換性
- 幹線への集中投資と地方路線の維持
- 延命と更新
- 維持と廃線
- 長期投資と短期収益

規格、車両、運行、経営、歴史のすべてにトレードオフを持たせることを基本方針とする。

## AIがプレイしやすい設計

Rails on Rail は、人間だけでなくAIもゲームをプレイしやすい構造を目指す。

AIが画面を画像として読み取ることに依存せず、ゲーム状態を構造化された形で取得し、人間と同じ操作体系を通じて行動できるようにする。

AIには権限を指定できるようにする。

例えば、以下のような段階を想定する。

- 状態の閲覧のみ
- 調査と分析
- 行動案の提案
- 人間の承認後に実行
- 指定された範囲で自律的に実行

さらに、地域、予算、操作対象、廃線や借入などの重要判断について個別に制限できる設計を目指す。

ゲーム内の自動化とAIへの委任は区別する。

自動化は、あらかじめ決められた条件と手順に従って行動する仕組みとする。

AIへの委任では、目的を与えられたAIが、何を調べるべきかを判断し、調査、比較、計画を行ったうえで行動する。

つまり、自動化では手順を指定し、AIには目的を指定する。

## 詳細シミュレーション

ゲーム内部では、可能な限り具体的な要因から状態や結果を計算する。

抽象的な万能パラメータだけで鉄道を表現することは避け、車両、設備、規格、輸送需要、維持状態などの具体的な要素が相互作用するシミュレーションを目指す。

ただし、詳細であることと操作が煩雑であることは分けて考える。

内部は細かくシミュレーションし、人間向けの画面では地図、表、警告、集計を使って情報をまとめる。必要に応じてAIへ調査や管理を委任できるようにする。

**内部は細かく、操作は集約する。**

## 開発方針

- 2Dを基本とする
- 当面はWeb技術を使用する
- TypeScriptを中心に開発する
- シミュレーションと描画・画面表示を分離する
- 車両、規格、技術などは可能な限りデータとして定義する

## プロトタイプを動かす

```bash
npm install
npm run dev
```

表示されたURLをブラウザで開くと[ホーム画面](docs/features/home-screen.md)を表示する。「新規ゲーム」で空の自由マップを開始し、「続きから」「ロード」で保存から再開できる。自由なマップを移動・拡大縮小しながら線路を敷設し、線路上へ駅を設置できる。複数駅を停車順に選ぶと運行経路を作成し、試験列車を走らせられる。

自動テストと本番ビルドは次のコマンドで実行する。

```bash
npm run test
npm run build
```

## 東上線の車庫・留置線マップ

`npm run generate:tojo-depots` で既存OSM取込から生成し、開発サーバーの `/?map=tojo-depots` で開く。森林公園・下板橋・上福岡などへ一覧から移動できる。[内容と基準データ](docs/features/tojo-depot-map.md)。
